# Hallmark 视觉规范

## 用户确认的方向

2026-10-06：用户要求组件有颜色和成熟的设计，并指定龙海的[《人人都是 UI 设计师》](https://x.com/longhaiqwe123/status/2106216781174251724)为设计参考。已阅读正文；文章整理自 Refactoring UI。其方法强调先建立信息层级，再用色阶、间距和操作权重完善视觉。灰度适合检查结构，交付预览应呈现完整配色。

蓝白是当前工作方向。A 表格、B 图文列表、C 商品卡、D 看板仍在选型讨论中，不能把建议当作用户已选定的模板。

用户进一步明确：这些规范用于我和 DSH Agent 制作模板。应给 Agent 直接编辑普通前端源码、复用设计并查看真实效果的能力。实际使用出现问题时再做局部修复，不预先收紧组件、布局、样式、依赖或数据表达。现有 ViewSpec 限制是待改造现状，不应复制成新源码模板通路的长期规则。

## 本项目的应用方式

- **一套可复用的主题。**页面底、卡片底、正文与辅助说明有明确层次；主色覆盖重点操作与选中态。成功、待处理、失败各有稳定颜色，辅以文字或图标。颜色须有浅背景、边界、正文与交互态，不能只定义几个孤立色值。
- **围绕用户任务安排重点。**商品名、关键属性与主要动作优先；ID、来源和时间保持可读但降低权重。辅助操作避免与“附加到聊天”争抢注意力。字段含义可能混淆时保留标签，例如采购成本、售价和导入时间。
- **按内容建立节奏。**同一商品的信息靠近，不同商品与模块适当分开。大区域可以留白；窄栏调整列数、标题和排列方式，避免把宽表整体缩小。不同字号的同排文本检查基线。
- **丰富但克制。**真实商品图片、浅色选中背景、少量强调边界与轻阴影都可建立层次。普通列表减少重复框线。大面积高饱和底色、所有按钮同样醒目，会干扰操作。
- **真实状态也要完整设计。**区分无数据、筛选无结果、加载中和读取失败。给出原因与当前可用的下一步；筛选无结果时保留清除筛选入口。避免用演示数字、假图片或无作用按钮填满空白。
- **用实际尺寸检验。**关注长商品名、中文与英文混排、图片缺失和批量选择。窄栏与宽标签页分别检查；文字、图标、状态和键盘焦点都要清楚。图表颜色配合图例与文字，图片文字优先放在独立清晰的区域。

## 配色与实现

默认延续 Hallmark 蓝色强调、浅色页面底和白色卡片；为蓝色、灰色及业务状态准备对应色阶。深色主题使用独立的背景与前景组合，不能把浅色白底直接固定到所有主题。具体色值与强度随实际预览调整。

当前源码路径使用普通 React/CSS 实现色阶、字重、按钮层级、图片与状态。以 Host 的 authoringGuidance 和当前 Apps 网关为入口，实际构建并查看标准预览截图；不再调用旧 hallmark_app_info 或按旧源码流程探索。用户已授权这条源码路径，制作组件时无需再次请求开发插件的许可。

旧 ViewSpec 渲染器的 theme/options 仍有部分字段未接入呈现；这些限制不适用于源码工程。预览和 DSH 使用同一 dist，分别核验真实宽窄布局、图片、状态和操作。

生成预览前，检查“最先看哪里、主要做什么、颜色是否有一致含义、窄栏是否易读、异常状态如何恢复”。工具调用成功只证明生成链路完成；视觉验收需要实际渲染结果。用户仍在选方案时，以可比较的彩色预览和原版来源支持讨论。
