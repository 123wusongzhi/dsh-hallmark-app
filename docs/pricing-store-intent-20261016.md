# 经营设置：一次性外部切店意图与正确连接路由

比较基线为公开 `f6404b5465c4b43f859567e1fc635327f78103bc`；原探针使用的本地 `069817a535769add648295f88086132768e39b00` 生产代码相同。

## 原行为与风险边界

1. 编辑店铺 A 的经营规则未保存时，工作台外部改为 B；原页面因 dirty 忽略这次变化。保存成功后仍停 A，不会补处理 B。页面与保存请求始终明确为 A，没有证据称误写 B。
2. 曾在设置页明确选过连接 X 后，工作台改为另一连接 Y 的店铺 B；原请求拼接 connectionId=X 和 storeId=B，真实服务拒绝 STORE_NOT_FOUND。没有显式连接时，原服务已经能够按 storeId 正确推导 Y。

实际 React、隔离 fetch 与真实 BusinessSettingsService.read/本地 HTTP 共同验证。sessionId 在 HTTP 层仅检查会话存在，进入共享店铺规则服务前剥离；不把这种共享设置语义描述成跨任务安全事故。

## 实现

- 只记录真正到达的外部店铺变化；规则 dirty 或保存中显示待处理意图。可明确不跟随、继续编辑原店；保存成功或明确确认放弃后消费一次，失败保留。
- A→B→A 取消，B→C 替换，旧确认失效；后来用户独立选店优先，未变化的工作台属性不在普通保存后抢回选择。
- 外部切换按目标 storeId 读取，省略旧显式 connectionId；成功后才安装新连接/店铺/规则。失败显示“尚未切换、仍显示原店”，禁止向不确定目标写入，可重读、另选或取消继续原店。
- 新建店铺或连接表单尚有编辑时不自动清空或切换；不新增凭据缓存、持久化或自动提交。测试只使用占位输入。
- 保存后新输入的店名/占位字段不会被重读洗掉；服务端规范化的店名/启用状态回填为新基线。连接表单编辑需先保存或恢复原值，避免重新读取暗中丢失。
- 包装子区仅在跨店读取等待期间暂禁新输入，未改包装业务或保存协议；避免旧连接的编辑在切换时被卸载。
- 保留原第10项规则重新读取内联确认，不使用全局同步对话框。手动重新读取不会隐式接受待处理的切店意图。
