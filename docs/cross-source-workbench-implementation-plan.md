# 跨接口组件工作台实施计划

日期：2026-10-09

## 用户体验

以已确认的三张蓝白设计图为基准，共用一个组件草稿：

1. **素材库**：图形缩略卡片选择组件，右侧真实预览；店铺独立选择，数据目录不按 Bill、Helen 重复。
2. **调整显示**：预览保持可见，右侧管理列的名称、顺序、显隐和密度；复杂模块组合设置按需展开。
3. **添加信息**：中文搜索和来源分类，以字段卡片展示含义、来源、示例；允许一次选入价格、库存、销量等不同接口字段。

字段选择必须改变真实服务端查询；返回上一层不丢配置。现有素材、采集箱、SKU 联动、保存组件、模板和源码工作副本继续可用。

## 数据契约

- 在 Hallmark Provider 新增只读 `hallmark.ozon.compose`，以版本化 recipe 定义字段和行粒度，复用现有十类规范化接口。
- 商品粒度通过商品 ID 与 SKU 的已确认映射关联；订单/包裹粒度使用包裹身份。明确日期、仓库和活动条件；不将包裹费用无规则复制到每个商品。
- 关联侧完成必要分页，形成可分页的组合快照；游标绑定店铺、连接版本、recipe 和筛选条件。
- 缺失、空结果、失败分别呈现，不以 0 替代未知。金额沿用原币种；字段带来源和语义说明。
- 字段稳定标识独立于语义 role，允许不同来源的同名字段共存。
- 组合草稿可真实预览，但不会每次点击都写入共享数据目录；明确保存时登记可复用版本并锁定引用。

## 复用

- Agent 先发现已封装数据源、组件和模板，再按需创建、真实验证并保存组合。
- 组件与模板保存数据源版本引用；打开时注入目标店铺上下文，避免带入旧店铺数据。
- 源码组件通过统一 Apps SDK 读取绑定、刷新和分页；不重复实现 Ozon 请求、身份关联或密钥管理。

## 分工和顺序

1. 后端：组合字段目录、执行器、Provider 描述与测试。
2. 界面：三屏视觉层次、跨接口字段选择、商品经营表和现有操作迁移。
3. 复用：Agent 描述、数据源解析、组件/模板上下文、源码使用说明和验证。
4. 主任务：稳定字段标识、草稿预览/登记、统一接口整合、运行验证和安装。

上述模块并行开发，共享契约先固定；保留已有未提交成果，不操作其他任务服务。

## 验收

- 同一商品表显示商品、价格、指定仓库库存、指定期间销量；跨页商品匹配准确。
- 三个入口切换、添加字段、改名/隐藏/排序、保存重开、切店重读均可操作。
- 同一 recipe 经工作台、Agent 和源码绑定读取一致；模板在另一店铺打开不沿用原店铺绑定。
- 测试覆盖重复语义字段、错误关联、分页、缺失、上游失败、游标作用域与版本隔离。
- 类型检查、构建、相关及完整回归测试通过；独立 4196/36995 实例更新并完成真实 API 和浏览器验收。
- 最终记录实际结果、截图与仍有的数据限制，不以概念图或演示值代替真实接口验收。

## 追加：有生命周期的数据缓冲

用户追加要求：有效期内复用数据；过期自动读取接口，并允许手动更新最新数据。

- 默认来源有效期 3 分钟。返回实际获取时间、到期时间、下一次刷新时间以及是否保留旧数据。
- 可见的工作台和源码组件到期自动刷新；隐藏页面暂停，返回时过期则刷新；不重叠发起同一请求。
- “立即更新”绕过普通有效期，但遵守平台限流。刷新时保留当前内容，成功后整体替换。
- 限流或暂时不可用时，仅复用之前完整读取的结果并明确标识过期及重试时间；未知值不填零。
- 新数据源登记不能使用过期缓存作为验证依据。缓冲和刷新策略不固化店铺，不改变保存的数据源引用身份。
