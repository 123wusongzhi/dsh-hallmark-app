# 上品草稿内容修正体验（2026-10-16）

## 范围与基线

- 基线：`fd95bc22929bfbfa850e0312357322578287a10c`。
- 用户任务：已有上品草稿提示缺少商品标题或图片时，补充实际要发布的内容、检查原属性及销售组成不变，然后明确保存草稿。
- 生产入口：应用工作台 → 经营操作 → 含 `listing` 行的批次。新增 `ListingDraftEditor` 使用现有父级草稿状态和 `revise` 路径；不创建新业务接口。
- 本轮实现和功能测试不等于原生 DSH、真实商家账户、图片服务或平台发布验收。无真实发布，无商家写入。

## 原版可观察问题

1. 上品行的商品列只有「查看 / 编辑完整内容」，普通字段必须在较窄的 JSON 编辑器中修改。
2. 展开完整内容，修改 `name` 后，「保存草稿」仍然禁用，「刷新批次」仍然可用。
3. 此时刷新批次，刚输入的标题被接口返回的原草稿覆盖；没有保存调用。
4. 原流程必须知道 JSON 字段名、保持语法正确并先点「应用字段修改」，才会进入父级的未保存保护。

隔离复现使用原版生产 React 文件（通过 `git show fd95…:packages/plugin-apps/client/business-operations.tsx` 加载）、真实 `BusinessOperations` 业务引擎、内存 SQLite 与 `/api/dsh-apps` mock。重新读取、保存等交互均走生产组件，不是静态 HTML。旧回归在期望可直接编辑标题处失败：实际可见标签输入数量为 0；另一次原版探针实际验证了上述刷新丢失行为。

## 改进

- 上品批次自动展示一张紧凑内容卡，明确当前销售货号，可切换同批次的上品行。
- 商品标题、商品说明直接填写；图片素材和发货包装可展开编辑。相关后端问题靠近对应字段显示；图片或包装有问题时自动展开对应区域。
- 输入立即进入本批次的未保存状态。无需 JSON，也无需「应用字段修改」。已有保护随即禁用刷新、切换批次和提交。
- 同批次切换销售货号、表格筛选不会卸载或丢失正在编辑的内容；下拉选项标出有未保存修改的行。
- 保存失败保留已输入内容；保存处理中禁用重复保存。
- 仅修改用户实际编辑的 payload 字段。原属性、未知平台字段、币种、定价方式、采购组成及未编辑行保留。重量/尺寸不猜测、不自动换单位。
- 保存仍仅调用 `revise`。审核及平台提交沿用原路径；结果未知、平台处理中和已完成行仍锁定编辑。
- 保留高级 JSON 入口用于本卡未覆盖的字段。该入口仍需先点「应用字段修改」，本轮未声称修复全部高级编辑交互。

## 前后任务对照

| 用户动作 | 原版 | 本轮 |
| --- | --- | --- |
| 找到标题修正位置 | 展开完整内容并寻找 `name` | 内容卡直接显示「商品标题」 |
| 改标题后保存 | 必须先应用 JSON，再保存 | 输入后直接保存 |
| 输入后刷新 | 未应用 JSON 可能被覆盖 | 结构化修改立即锁定刷新 |
| 切换销售行或筛选 | 编辑器随表格行挂载，局部文本可能丢失 | 编辑卡与父级草稿保留 |
| 保存失败 | 需确认原内容是否仍在 | 保留输入，可明确重试 |
| 发布风险 | 由原提交动作承担 | 保存仍不调用审核或平台传输 |
