# 组件性能与体验规格

新建或修改源码组件时，先按本规格设计，再用 Host 的标准 `checkRunner` 验证同一冻结构建。编译成功、截图正常与操作正确，还不足以说明首屏流畅；正式预览同时验证体验性能，通过后才能发布。具体测试条件、观测值和失败项以当前安装版本的检查报告为准。

本规格不限制页面风格或业务布局。用户可见内容应尽早出现，刷新时仍能查看已有商品，搜索和翻页应及时反馈，首屏资源优先于暂时看不到的内容。

## 受控性能门禁 v1

这是本项目的发布预算，不是通用 Web 标准。正式预览固定使用 420 × 900 与 1040 × 900 CSS 像素视口、冷缓存；HTTP 图片请求暂停 120 毫秒后，使用缓存、占位或本地原图响应，本地资源错误仍会使检查失败。检查初始页面，并在每个交互断言的 click/fill 动作后检查对应观测。预算由检查程序决定，组件和 `.preview/plan.json` 不能自行放宽。

| 自动观测 | 通过要求 |
| --- | --- |
| 首次数据与可见正文就绪 | ≤ 2500 毫秒 |
| 主线程最长任务 | ≤ 200 毫秒 |
| 总阻塞时间 | 每项长任务超出 50 毫秒的部分相加，合计 ≤ 300 毫秒 |
| 累积布局偏移（CLS） | ≤ 0.1 |
| DOM 节点数 | ≤ 3000 |
| 已渲染商品／表格行数 | ≤ 100 |
| 初始可见内容图；交互后新增请求的可见内容图 | 不得 lazy；首张为 high；加载前已留位置 |
| 隐藏区域图片请求 | 0 |
| 已加载 JavaScript | ≤ 2 MiB |
| 点击／输入到后续绘制反馈 | ≤ 250 毫秒 |

当前自动网络优先级检查覆盖可见、宽高均至少 40 CSS 像素的 HTTP 图片；较小图片和内联 data 图片不纳入这一项。不能通过缩小商品图来规避检查。隐藏区域指未显示的标签页或响应式布局；浏览器可提前请求视口附近的 lazy 图片，不要求屏外图片一律零请求。图片响应延迟是测试条件，不是用户真实网络的测量值。

首次就绪优先使用组件声明的 `data-ready`；未声明时，以桥接数据已返回且正文连续观测稳定作兼容观测。它不证明完整业务结果的每一行都已展示。点击／输入延迟测量真实事件到后续绘制机会，实际状态是否及时反馈仍由交互断言确认；准确的“更新中”可以作为反馈，不能冒充慢平台操作已完成。

初始采样检查所有实际可见 HTTP 内容图。交互后的图片优先级检查仅针对该动作阶段新发起请求且实际可见的图片；检查器滚动到操作按钮时，不会把已经加载的 lazy 图片重新判成首屏违规。隐藏请求和预留尺寸仍按各阶段实际发出的图片请求观测。

行数检查识别商品示例的 `data-product-row` / `data-composed-row`、标准 `tbody tr` 和 ARIA `role="row"`。自定义商品列表保留相应行语义或商品行标记；不能删除标记掩盖超量。DOM 总数检查覆盖整个组件，包括隐藏节点。

自动门禁覆盖上述观测；快照是否匹配店铺、后台刷新是否保留可操作内容、交互结果是否符合业务要求，仍需真实数据和交互断言验证。一次首屏通过不能证明真实外部数据请求、CDN 或全部设备都在同一时间内完成。

## 写源码时的决策

| 用户正在做什么 | 组件应有的行为 | 实现取舍 |
| --- | --- | --- |
| 第一次打开 | 数据到达后先显示名称、价格、数量等可用内容；图片在固定区域加载 | 不等待全部图片、可选上下文或远程统计才显示商品 |
| 重新打开或刷新 | 先显示范围与授权仍有效的成功快照；更新期间保留浏览、筛选和翻页 | 完整新快照成功后替换；临时失败保留旧内容与原时间；切店或权限变化不复用旧数据 |
| 搜索、排序、翻页 | 结果与控件状态及时变化；图片优先级跟随当前显示顺序 | 完整逻辑数据可以在内存中筛选，DOM 只渲染当前页或可视范围；大计算按实际输入缓存 |
| 查看首屏商品 | 优先请求首屏商品图，加载和失败都有稳定占位 | 使用官方缩略图字段；固定宽高；异步解码；首屏以外保持懒加载 |
| 切换标签页或布局 | 新显示的内容优先；隐藏内容不争抢图片请求 | `hidden` 或 `display:none` 不会阻止 eager 图片请求；优先级必须考虑实际活动标签与响应式布局 |

完整逻辑数据不等于一次挂载全部商品节点。不要为了少渲染而偷偷缩小搜索范围，也不要为了“全量”一次创建成千上万个 DOM 节点。采用本地分页或虚拟列表时保留清楚的总数、当前范围和用户操作状态。

### 商品图片

starter 提供 `src/Image.tsx`。优先复用它；自定义图片组件需要满足相同可观察行为，不以是否导入某个文件代替验收。

`priority` 默认关闭。按分页、搜索、排序后的当前显示顺序，为首屏商品图开启；隐藏标签、响应式隐藏布局、屏外长列表不能一起提升为高优先级。生成的 helper 使用固定尺寸、失败占位与 `decoding="async"`；图片 URL 改变后恢复加载。

在 React 18 中使用小写 HTML 属性 `fetchpriority`。更新已有图片时，先设置 `fetchpriority`，再设置 `loading`，最后设置 `src`；先解除 lazy 可能让浏览器按旧优先级启动请求。门禁保留请求时的属性与可见性，检查最终状态和首张可见 HTTP 图片实际请求的初始优先级；加载完成后改属性不会抹除原观测，同一图片已加载复用时也不强迫再发一次请求。

不要把所有图片设为 eager/high，不等待 `Promise.all(images)` 才显示列表，也不通过隐藏真实商品、删除必要字段或把加载时间转移到点击之后来通过检查。

## 验证范围与证据

使用 Host 返回的 `checkRunner.prepareRequest` 与正式检查请求。性能检查由标准预览执行，Agent 不另建 Host、CDP 流程或测试专用轻量页面。检查面对即将发布的冻结产物；业务交互计划仍维护在 `.preview/plan.json`。

视觉预览可使用缓存或占位图片；它只能证明布局与交互。性能检查使用受控资源和固定测试条件，观察组件的首屏调度、隐藏资源、DOM 和交互表现。受控测试不代表真实图片源站的耗时，也不承诺某个店铺、网络或设备上的绝对打开速度。报告时分清测试条件和已观察结果。

无图片、真实空结果或静态说明页按实际内容验证；不得加入假商品来通过业务断言。已有成功快照和首次无快照是不同状态，只有实际测过的状态才能写入结论。

## 失败后怎么修

先读标准检查摘要中的性能失败项、实际值与证据，再定位对应源码：

- 首屏迟迟没有可用内容：检查是否等待可选请求、全部图片、重复桥接读取或大块同步计算。
- 首屏图未优先、隐藏图已经请求：检查最终显示顺序、活动标签、响应式重复 DOM 和图片属性设置顺序。
- DOM 过多或操作卡顿：控制渲染范围，复用格式化器和稳定计算，避免搜索输入引发无关整页工作。
- 刷新后空白或状态跳回：保留有效快照和兼容 UI 状态，检查过期响应是否覆盖新数据。

修改源码后按既有 `begin` 流程创建新 attempt，重新构建并执行正式预览。只改未登记的交互计划时可复用符合条件的冻结构建，规则见 [检查与发布](check-and-publish.md)。同一请求重跑只恢复原结果；需要真实重测时按 [阶段重试](performance-cli.md) 执行。

性能失败或缺少当前要求的证据时，不能发布。不得手改报告、伪造 PASS、移除失败断言、关闭采样、放宽预算或改用另一份产物绕过检查。若检查环境无法运行，保留源码和错误证据，如实报告未完成验证。

更新 starter、SDK 或本规格不会自动重写已保存组件的 `dist`。未修改的历史版本仍是原冻结构建；用户要求优化该版本时，重开工作副本、修改源码、完成检查，再发布新版本。普通查看、刷新数据或原样保存不因此触发重建。
