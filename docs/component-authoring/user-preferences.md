# 组件体验与用户偏好

政策标识：`component-experience-v1`。适用于当前用户在 DSH / Hallmark 中创建或修改的素材、组件、模板和工作台，不推广为其他用户或其他产品的偏好；用户当前明确指令优先。本文件统一描述用户已确认的方向，不是声明所有历史组件已经完成改造。Host 的 `authoringInstructions.userPreferences` 会直接注入核心规则，`developerDocs.userPreferences` 指向本文件；不能只依赖 Agent 自行发现设计技能。

## 默认体验

- 蓝白风格、简洁且有清晰视觉层次。先用图片、字号、留白、位置和少量状态色帮助理解，减少说明文字、重复卡框和密集字段。详情按需展开，兼顾窄栏和宽标签页。
- 应用工作台默认显示“缩略图＋标题”的紧凑卡片，点击在顶部独立标签页打开完整组件，再点同一组件回到原标签。Agent 组件旁直接提供“添加到工作台”，不埋在折叠管理区。标签的关闭按钮清晰易点，直接关闭并保留恢复能力。
- 字段使用用户能懂的中文业务名称；单位、币种、口径以及不同来源的同名字段必须区分。接口字段名、路径、技术配置放在高级说明，不要求普通用户理解。
- 数据源按平台能力和字段共用。Bill、Helen 只出现在店铺选择，目录只保留一套“Ozon 商品资料”“Ozon 商品价格”等定义。组件配置可换店复用，具体店铺不写死在共享数据源中。
- 使用“工作台预览 → 调整显示 → 添加信息”的渐进操作。预览先让用户看见结果；调整显示管理列、布局和密度；添加信息可组合不同接口的字段。跨接口由后端按稳定商品/包裹身份、关联关系与数据粒度匹配，不按行号拼接，不能把包裹费用当单件费用。
- 优先使用平台已封装数据能力。缺少接口时由 Agent 按已有店铺授权扩展适配、字段映射与分页处理，真实验证后登记可复用数据源，普通用户不需要填写 API 路径或密钥。
- 提供搜索的列表明确搜索范围。按钮应显示进行中、成功或需要补充的原因；不能只禁用按钮让用户猜测是否生效。涉及方案切换时结果注明当前生效方案，试算与平台业务写入分开；具体字段与业务控件按组件任务添加，不把某个组件的配置扩展到所有组件。

## 全量数据与分页

全量指**当前店铺、筛选和查询范围的完整逻辑结果**，不等于一个 HTTP 请求返回全部商品。底层接口需要分页或多接口组合时，由 Provider 在后台处理批次、去重、关联和完整性校验，再产生一个完整快照。面向用户优先提供完整数据上的本地分页、全量搜索与排序，不把“下一批接口”当作普通分页体验。

开发期间只读少量样本来确认 schema；这不限制正式组件的全量体验。仍由能力支持的筛选条件准确限定范围，例如 `status: "on_sale"`，不把未知状态猜作在售。

接口受权限、数量上限、游标或查询窗口限制时，不得凭第一批就声称全量；明确实际范围和未完成状态，并在 Provider 层补齐能力。旧接口只有服务端分页时可保留已验证的 `readBindingPage` 通路作为明确标注的降级，不能在组件里自行 HTTP 请求、偷偷拼接不同快照，或仅把文案改成“全部”。此降级不改变全量体验的默认目标。

## 快照优先与后台刷新

默认有效期为 **15 分钟（900000 毫秒）**，覆盖此前 3 分钟的默认值。

1. 每次进入组件，优先立即显示同一数据范围内**上次成功的完整快照**，包括快照已经到期的情况。快照应可用于后续重新打开，不能只依赖当前组件内存；授权核验仍必须通过。
2. 未到期时复用；到期、恢复可见时发现已到期、或用户手动刷新时，后台更新。用户继续浏览、搜索、排序和翻页，不清空列表，不用阻断遮罩让用户等待刷新。
3. 同一范围合并重复请求，遵守限流退避。新查询全部成功、身份和完整性检查通过后，再原子替换完整快照。中途批次或失败结果不能覆盖成功快照；跨接口组合也不能悄悄把不同批次或时期当作同一完整快照。
4. 限流、网络波动或临时错误继续显示有效授权下的旧快照，保留其真实来源时间和上次成功时间，以简短状态提示后台稍后更新。读取缓存不能把旧时间改成当前时间，也不能把“已触发”说成“已更新”。
5. 首次确实没有完整快照时，显示轻量“正在准备首次数据”状态，允许重试；不得编造业务数据、用演示数据替代或假称秒开。可呈现真实进度，但不把未完成批次发布为完整快照。
6. 完整更新后尽量保留兼容的搜索、排序、页码与选择；记录已消失时清理对应选择，页码越界才回落。自动后台刷新与真实平台业务同步不是同一件事，以能力明确支持的语义为准。

源码组件使用 `apps.refreshing` 表达后台更新，并继续渲染 `apps.data`；`apps.loading` 只用于首次尚无可用数据的准备状态。Provider 的 `payload.cache.refreshing` 与 `nextRefreshAt` 驱动 SDK 定时续读，不自行叠加无限轮询。不能因点击刷新就把整张表替换成 Loading，也不能只凭刷新请求返回就宣布新快照已完成。

## 数据边界与真实性

缓存必须按连接及其配置/授权版本、店铺和完整查询参数隔离。切换店铺、查询或数据定义后只能读新范围的快照；没有时进入首次准备。明确 401/403、授权撤销、店铺或连接停用时，不以“体验优先”为由继续暴露旧业务快照；提示恢复授权，不混用其他店铺或曾获授权的数据。

图片、规格、采购价、运价、利润或库存缺失时显示“待补充”“暂无数据”或明确原因，不能补为 0 或装饰性假数字。真实 0 与未知必须不同。金额标明币种，不能直接合计不同币种；参考利润保留公式和来源，不冒充实际结算。

涉及物流试算的组件还需遵守该业务要求：渠道从实际 API 获取并匹配已证实的商品/仓库条件，渠道名称不是计费或重量规则；接口未提供费率时明确待确认，只能使用用户确认费用或明确标为参考的试算方案。试算只更新组件配置和计算结果，不修改 Ozon 售价或提交物流订单。此要求不意味着所有组件都应添加物流选择或费用输入。

## 交付检查

按实际支持能力验证：重新打开先看到完整旧快照；过期与手动刷新期间仍可搜索翻页；完整成功后更新；限流和失败保留旧结果及原时间；切店与权限失效不泄露旧数据；搜索排序覆盖所声称的范围；首次无数据、字段缺失和操作反馈清楚。未实现或未验证的项目明确说明，不能以说明文档代替运行证据。

## 侧边栏与收藏

侧边栏的「本次会话」是临时组件主入口；继续编辑时更新同一个工作副本，不为每轮调整新建重复组件。详情在独立标签打开，编辑状态用简洁文雅的提示，已有内容可继续查看。用户主动点击星标才加入「我的收藏」；保存到素材库、添加工作台和收藏是三个不同动作，Agent 不自动替用户收藏。关闭详情标签不代表删除组件或结束制作。
