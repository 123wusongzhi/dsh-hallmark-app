# 加载、刷新与分页

默认体验由[统一用户偏好](user-preferences.md)规定：当前范围的全量逻辑数据在后端组成完整快照，前端本地分页、全量搜索和排序；重新打开先显示上次成功完整快照，15 分钟到期或手动刷新时后台更新，完整成功后才替换。刷新不阻塞旧结果操作，临时失败保留旧快照与原时间；首次没有快照才进入轻量准备状态。跨店、参数和授权必须隔离。

下列 `readBindingPage` 描述的是已有绑定协议，以及仅提供服务端分页能力时的降级通路，并不将“只显示当前接口批次”设为新组件默认。Agent 先确认 descriptor 和 payload 的完整性语义；没有全量能力时补 Provider 或明确范围，不能将一批包装成全量。

从组件库打开已保存组件、重开编辑或使用模板时，宿主沿用保存的精确 `appId + connectionId`，并为当前聊天启用这些已有连接引用；不会选择默认连接、迁移凭据或改变其他聊天的绑定。连接已删除或全局停用时，打开会先给出恢复/启用指引，不创建工作副本。新聊天沿用保存的查询条件，翻页和刷新使用当前聊天身份。

- `useApps` 建立桥接并读取 getData。它不会因为 binding.state 为 empty 就自动查询业务数据。
- 后台刷新用 `apps.refreshing` 显示轻量状态，继续渲染 `apps.data`；`apps.loading` 用于首次准备。Provider 的 `cache.refreshing` / `nextRefreshAt` 供 SDK 定时续读，不为刷新替换整个表格或另加竞争定时器。
- 首次得到 empty binding 且没有完整快照时调用一次 `refresh([bindingId])`。用 ref 记住已初始化的 binding，失败显示错误和重试按钮，不建立循环重试。有缓存的正常打开先显示缓存，不为等新请求清空它。
- `refresh([bindingId])` 读取绑定的基础查询并更新 apps.data。完整数据组件保持兼容的本地搜索、排序和页码；旧服务端分页示例刷新后回到第一页、清空游标历史，是其分页协议行为。
- `readBindingPage(bindingId, nextCursor)` 沿用绑定的条件、字段和页大小，只更换 cursor；payload/resources/revision 一起更新到 apps.data。
- 上一页使用组件保存的已访问游标；不要从页码猜服务端 cursor。第一页传 null。
- 分页或快照重读期间避免同类请求竞争，成功后再更新页码，失败保留当前页并展示错误。耗时平台同步使用独立 busy 状态并合并重复同步，不阻塞旧快照搜索和翻页；同步成功后等待在途分页结束，再 refresh 并明确回到第一页。
- 优先在完整快照上搜索、排序和统计。降级到仅当前服务端页时，界面明确“当前页”；没有完整数据或后端全局查询能力不能声称全局搜索。

`invokeCapability` 用于独立查询或明确提供的平台同步能力；服务端游标分页使用 readBindingPage，本地完整快照分页无需请求接口。跨接口组合及批次读取由 Provider 负责，组件不自行 HTTP 请求或拼接接口结果。

分页 payload/resources/revision 按组件实例保存在 Runtime，getData 对同一实例返回当前页；不修改共享绑定的基础查询，也不影响其他窗口。Agent 普通读取视图绑定仍读取基础快照，不会自动获得侧边栏当前页；不得声称 Agent 已看到用户翻页后的内容。附加到聊天暂未开放。

“刷新快照”不等于触发外部平台同步。显示 sourceDataTime；只有真实业务能力明确提供平台同步时才承诺实时同步。

## 保存与历史

工作台首页以缩略图和标题展示常用组件，不在目录中挂载完整组件或请求业务数据。点击卡片在应用顶部打开独立标签，再次点击同一组件定位已有标签；内置素材实例与 Agent 保存组件都遵守这一交互。标签的关闭按钮直接关闭并保留内容，不删除工作台入口或素材。

Agent 组件预览顶部和聊天侧栏均提供“添加到工作台”。该操作先按现有验证与版本冲突规则保存当前已确认展示，再固定保存版本；“我的组件”中的添加按钮直接固定已保存版本，不重复保存。工作台引用同一组件最多一条，库中的版本、源码与历史仍由原组件持有。移除工作台卡片仅移除入口。未发布源码不能通过此入口跳过预览和正式展示确认。

在同一个聊天再次打开同一保存组件、同一版本及店铺时，`open_component` 默认定位已有工作副本；`begin(mode:open_saved)` 继续该副本的可恢复工程。先使用返回的 `viewId`，不要因为已有标签就再新建。不同店铺、明确选择的其他版本或明确要求另做一份时仍可独立；确需新副本用 `newCopy:true`，不能用它绕过旧副本的保存版本冲突。`mode:new` 仍表示用户明确创建新组件。

关闭工作副本会保留源码和历史，并持久移入“已关闭工作副本”；重新进入页面不会再把它当作打开的标签。关闭不是删除素材库组件；从关闭列表恢复会使用原来的视图身份。

用户明确要求保存后，调用 `apps.authoring.save_component`，携带当前 `viewId` 和 `expectedViewRevision`。从组件库普通打开或重开编辑的已验证组件，如果当前构建、设计和绑定定义与保存版本一致，可以直接保存；仅刷新数据或翻页不要求重新构建、预览、发布。未发布的源码编辑不会被保存为新设计；要保存这些修改，先完成检查与发布。新发布仍在加载时，等待展示确认后再保存。

`update` 使用当前工作副本的 `sourceComponentId` 和 `baseRevision`。成功回执 `component.view` 给出新的目标和基线，后续保存继续使用它；`save_as` 成功后更新目标是新组件。不要继续使用打开时的旧基线，也不要自行读取库中最新版本来提高旧副本的预期版本。

`selectedSourceRevision` 保留选中的历史版本，`baseRevisionAtOpen` 保留打开时库中最新版本。它们用于说明来源，当前更新基线以 `baseRevision` 为准。未改的历史版本可直接保存为新增版本；只有修改设计时才重走检查发布，旧版本不被覆盖。其他旧工作副本发生冲突时，保留它并让用户查看最新版或另存。
