## 限流时继续使用缓存

candidate49 补齐用户体验：上游限流或暂时不可用时，同店铺、同查询、同连接版本的成功数据继续显示，保留原成功时间和当前页，仅轻提示等待更新。正常有效期仍为三分钟；到期是尝试更新的时间，不是强制清空缓存的时间。后台尊重平台返回的重试期限，手动更新也不会突破冷却。

某个辅助来源首次没有成功缓存时，其他已取得的数据继续展示；该来源标记为缺失，对应字段为未知值，不用零补齐。商品或包裹主数据本身缺失时不虚构行。权限、身份或连接配置改变时不使用旧缓存掩盖问题；部分数据不能验证成完整的新数据源。

## 有效期与刷新

组合数据默认有效期为 **3 分钟**。缓存按连接版本、店铺和来源查询条件隔离，同一来源的并发读取合并。页面可见时按接口返回的下次刷新时间自动重读；隐藏后暂停，恢复可见时检查过期。

「立即更新」要求重新读取普通来源。Ozon 流量接口的 60 秒冷却仍然生效；在冷却、限流或暂时网络故障期间，仅保留此前完整成功的结果，明确显示过期和下次重试时间，不伪造新的获取时间。权限错误不回退成可用数据。新数据源不能依赖过期数据完成验证登记。

刷新过程中保留当前内容，成功后更新；失败保留旧内容并重试。切换店铺、组件或离开页面会取消对应请求并丢弃迟到响应。源码组件通过统一 SDK 使用相同规则；手动刷新回到第一页。

数据时间分为接口记录的业务时间与本次实际读取成功时间。缓存刷新保证按周期重新读取接口，不表示 Ozon 自身的数据没有延迟。
