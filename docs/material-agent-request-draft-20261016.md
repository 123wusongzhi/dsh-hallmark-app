# 素材页 Agent 需求草稿保护

基线 `9384e50`。本项是独立的需求正文丢失问题，不重复计入既有组件配置关闭保护。

## 实证问题

在素材库配置组件，点击“没有需要的数据？让 Agent 创建数据源”，手工补充需求，再点击“收起”后重开，正文被自动模板替代。重复点击创建入口也会直接覆盖正文。仅修改需求而没有修改组件配置时，关闭素材库不提示，重新打开无法恢复。切换工作台标签再返回则保留，作为对照。

生产 React `AppsWorkspace`、`MaterialLibrary` 和子组件实际事件处理器已复现；HTTP 完全由本地 transport fixture 拦截，无外部 agent、真实商家或凭据写入。本次没有浏览器视觉验收或发布。

## 最小变更

- 将正文与折叠状态拆开；“收起”只隐藏，同次编辑中重新打开保留原需求，并明确提示恢复的是原草稿。
- 清空正文不再导致编辑框消失；空白需求禁用交接按钮。
- 仅手工修改、尚未成功放入原聊天的正文纳入现有局部关闭保护。自动模板、净零编辑不额外提示。配置保存不等于需求保存。
- 关闭提示准确区分配置与需求；旧确认不能丢弃更新后的文本。
- 成功交接只确认对应正文快照，明确“尚未发送”；交接中继续修改的内容仍受保护。
- 按 app/session/instance 隔离，无新增全局持久缓存。不同会话不继承需求。晚到的 prepare 响应在 native handoff 开始前失效；已开始的 native handoff 不能由此取消，但迟到回执不会修改新 owner 的状态或成功文案。
- 保持现有发送时当前数据源连接的准备语义；不改变 native bridge 或自动发送行为。

范围：普通同页折叠、重复创建和标签切换保留正文；关闭后放弃不会持久恢复。切换 app/session/实例仍按隔离边界清空本地需求。此次未扩展为跨边界草稿存储。
