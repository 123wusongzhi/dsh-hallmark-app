## 3. 精确 Host 契约及设计约束

以下键来自先 `cordis_inspect_list` 再 `cordis_inspect_query`，Inspect 是只读契约发现，不是业务 Service 调用入口。

### 3.1 原生工具

```ts
ctx.tools.register({
  name, description, parameters,
  output: {
    schema: resultSchema,
    render: (_args, value) => [{ type: 'text', text: JSON.stringify(value) }],
    // 可选 presentationMeta: (_args, value) => JSON-compatible metadata
  },
  async execute(args, exec) {
    // exec.agent?.id 是宿主传入的会话身份，不能从工具 args 信任 sessionId
    // exec.signal 必须传递到 HTTP；返回声明的 JSON value，不返回旧版 ToolResult
  },
});
```

- `ToolDefinition.output` **必填**，含 `schema` 与 `render`；旧 `execute` 直接返回 `{content,isError}` 的惯用写法不适用当前核心值契约。
- 原生执行结果由 runtime 材料化为 `ToolExecutionSuccess {isError:false,value,content,...}` 或 failure；业务包络作为 value，由 output.render 投影给模型；自定义视图应使用当前 toolview 节点/metadata，不伪造卡片类型。
- `ToolSchema` 允许 name/description/parameters/deferLoading。`readOnly:true` 不是本次 live 契约声明字段：读写类别保留在能力层工具目录，不能假装宿主会处理任意 metadata。
- 若使用 `defineTool`，需按当前参数 spec 适配；直接 register 也受正式 JSON schema 校验，不要通过弱类型蒙混。
- output schema 支持的是宿主约束的 JSON Schema 子集。可空字符串用 `oneOf`，不是 `type:['string','null']`；正式服务工具 Schema 须经过该 runtime 校验。
- `get(name,scope?)`、`schemas(scope?)` 使用 scope；全局注册在所有会话发现，需要执行门禁，不代表所有会话都获得应用授权。

### 3.2 应用状态、命令与指令

- `ctx.commands.register({name:'hallmark',description,input?,handler(invocation)})`：handler 获 `invocation.agent.id`、rawInput、signal；返回 `{kind:'success',text?}` 或 `{kind:'error',text}`。这是用户命令，不能把人类命令重新暴露成 agent 操作工具绕过 UI 授权。
- `tools/pre-execute(exec,next)` 为 **waterfall**：无关工具必须 `return next()`；拒绝返回 `{kind:'deny',reason,info?}`。不能当普通 emit，也不能无条件 allow 覆盖其他插件的限制。
- `ctx.tools.guard(exec=>reason|undefined)` 是同步 monotonic guard，适合恢复后活跃状态缓存；若状态需要异步查 SQLite/服务，使用 waterfall 与工具内自检。unknown/missing agent 不放行。
- 激活/关闭先持久化服务状态，确认成功后更新 plugin cache；恢复未完成或服务不可用都 fail closed。
- `ctx.systemPrompt.context({name:'hallmark-app',order,text(context)})` 是每模型步动态贡献。`context.scope` 类型为 object，不应当 sessionId 字符串。当前真实源码 [Agent helper](../../test/spike/evidence/dsh/node_modules/@deepseek-ai/dsh-agent/lib/index.js#L291-L295) 的 `assembleContextFor(agent,signal)` 返回 `{agent,scope:agent,signal?}`；[agent-loop](../../test/spike/evidence/dsh/node_modules/@deepseek-ai/dsh-agent-loop/lib/index.js#L907) 每模型步用该 helper 调用 assemble。可读取 `context.agent?.id`（Agent augmentation）并验证 Agent/scope identity，或从 scope 对象结构安全解析 id后与 live Agent registry 身份比对，缺失/恢复未就绪返回空贡献。
- 不向会话历史永久追加无法删除的应用规则，不通过全局静态 section 污染其他会话。动态 text 没激活返回空字符串；以上是源码 identity 证据，现场 prompt 组装验收仍未运行。

### 3.3 宿主认证代理

`ctx.connection.fetch.register({path,methods:['GET'|'HEAD'|'POST'],requestBody:'buffered'|'streaming',fetch(Request):Promise<Response>})` 注册精确路由。该现有认证通道优于直接 Client 请求独立服务并泄漏本机共享密钥。

- 本机能力服务仍只监听 loopback，插件 Host 校验目标服务 URL，携带密钥与取消 signal。
- UI 请求如应用激活/关闭、读取视图/入口/刷新经认证代理；插件自行校验 sessionId，不能因为在本机就允许跨会话任意切换。
- 如改用 `webServer.register`，必须显式使用 Connection admission/Origin/Host 检查；裸 WebRoute 不能假定自动认证。
- 独立能力服务留在独立进程承载业务/后台调度。插件仅代理，不把 Hallmark 核心迁入 DSH。

### 4.2 实施约束

```ts
ctx.slots.inject('conversation.input.left', () =>
  ctx.slots.register({name:'conversation.input.left',id:'hallmark.apps',order:50,label:'应用'}, AppsButton));
ctx.slots.inject('tool.call.toolview', () =>
  ctx.slots.register({name:'tool.call.toolview',key:'hallmark_render_view'}, HallmarkView));
```

此为拟用 API 示例，尚未在当前 UI 加载。React 必须来自 npm client manifest 注入/外部共享模块，不使用动态 runner Builtin 的 `ctx/React/host/styles` 假装 npm client 环境。

- 注册前等父 Slot 声明，list 要 id、keyed 要 key；同 key/priority 冲突会失败。不要覆盖 root 或抢占核心 id。
- scope 由声明 Slot 决定，不能任意把 session props 当 root props；跨 session 的状态/数据不能共享一个不分会话的 hook store。
- `ctx.slots.renderSlot` 只能 ctx-level render **root**；业务组件不能调用它去渲染任意 child。组件自己的 `renderSlot` 是父 entry 声明 children 后交给 props 的授权绑定，销毁后失效。
- 配色采用 live token `--dsw-alias-bg-base/label-primary/border-l1/brand-primary/state-*`，实际浅深对比仍须截图/视觉验收。

## 6. 后端调用链路与未定项

确定的层次：DSH native Tool → 插件 Host 会话/门禁 → 独立 service 工具网关 → core/presentation/store → Hallmark HTTP adapter → 现有 Hallmark，保留原始字段与业务记录。

- 普通数据读、加工、刷新和写工具分开；UI 打开只读快照，不触发平台业务写；独立 scheduler 不引用写工具模块。
- 平台读白名单经已有合法内部任务上下文，而不是暴露任意 URL/method。H2 确认没有纯店铺任务创建路由：复用合法 Listing Task，无上下文返回 `TASK_CONTEXT_REQUIRED`，不能随意采集/挑商品补上下文。
- 上品按用户指定 collected item/store/SKU 自动 assignment 后走受控 import（如该路径已启用）；不得编造 HTTP prepare/deliver，也不宣称四工具或 import 路径已端到端跑通。
- H1–H5 完整结论已落盘并读取：[Hallmark 契约记录](../hallmark-contracts.md#L1-L135)。实际健康/店铺只读请求均 unavailable，无真实业务写入；20项合成夹具测试通过；H3 没有完整合成上品链路，不算真实跑通。下表为接入决策摘要，准确请求/返回以该记录为准。

| 编号 | 核实结论及对方案的修正 |
| --- | --- |
| H1 | [完整方法/请求/返回/鉴权表](../hallmark-contracts.md#L10-L55) 已源码盘点。库存写 `POST /v2/products/stocks`，回读 `POST /v2/product/info/stocks-by-warehouse/fbs`；sync全部Ozon店铺而非单店，store-products无源端分页过滤。不把尚未暴露的归档、采购价、促销、类目、图片、优化等能力标已完成覆盖 |

### 8.3 浮窗工作台与聊天授权分离

用户追加：左sidebar应用按钮打开DSH内独立浮窗应用列表；Hallmark左键开Workbench，右键“启动聊天”才激活当前原聊天。工作台展示常用/保存组件与自由搭建（layout/widget/binding/theme表单、临时preview、明确save）。工作台不得为了读取配置伪造chat activation。

Host认证精确桥 `/api/hallmark-app`：

- GET resource=`saved/templates/datasets/view/viewData`（viewId按需）→服务`/ui/*`裸配置/快照值，独立于chat active。
- GET resource=`state` + sessionId；POST action=`activate/close` + sessionId →严格真实会话验证与持久状态，不允许模型args指定。
- POST白名单 action=`preview/update/saveComponent/saveTemplate/manage/openEntry/refresh` →对应`/ui/render/update/save/save-template/manage/open-entry/refresh`。参数严格白名单，save动作marker由Host生成，Browser不可传userRequest或任意tool/path/args。
- preview/update/openEntry返回裸ViewSpec（id字段）；保存行为记录由服务依据明确按钮自动生成真实UI来源说明，不伪造聊天原话。openEntry仅读取已保存binding并生成临时Spec，不做source query或平台写。
- 工作台refresh经独立只读刷新，不走业务write。服务`/ui/*`也强制Bearer/loopback/OriginHost检查；Browser不持有service-key，依宿主same-origin认证载体。
