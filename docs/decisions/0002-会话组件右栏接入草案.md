# ADR 0002：本会话组件右栏（只读契约审查与设计草案）

状态：**设计，不是已实现或现场验收**。复用原聊天、原 right sidebar/原 docking tabs；不改 core/frame，不新建聊天 UI，不猜示例商品/库存/利润数据。

## 1. 原生右栏扩展契约

证据是当前 0.2.0-rc.2 实际 ASAR 的 [ui-sidebar-right client 实现](../../test/spike/evidence/dsh/node_modules/@deepseek-ai/dsh-client-ui-sidebar-right/lib/client.js)。Lead已通过live Slots Inspect确认两个keyed/session pane槽及definition.id dispatch，目前无Hallmark新TabType；Generic Service Inspect对两个reflection faces返回no catalogued Service（catalog仅静态8项），据此走下述公共SDK/实际源码fallback。不能将契约证据称作新插件live注册成功。

公共反射面实际提供于 [9073–9074](../../test/spike/evidence/dsh/node_modules/@deepseek-ai/dsh-client-ui-sidebar-right/lib/client.js#L9073-L9074)：`sidebarRightTabs`（类型注册）和 `sidebarRight`（导航 controller）。两者不是早期 Service catalog 已列出的 Service 类，不以包名自行猜方法；按实际公共源码与 Lead live 验证使用。

### 1.1 必须两阶段登记

1. `sidebarRightTabs.register({id,kind,title,...})` 注册新类型；id/kind均使用 Hallmark 独立命名，不 shadow builtin kind，不提供 fallback priority。
2. `slots.inject` 等父槽声明后，注册 `sidebar.right.pane.tab` 与 `sidebar.right.pane.tab.title` 的 keyed occupants。**Slot key 是 TabDefinition.id，不是 kind**，源 [5551](../../test/spike/evidence/dsh/node_modules/@deepseek-ai/dsh-client-ui-sidebar-right/lib/client.js#L5550-L5553) 为 `entryKey:definition?.id ?? tab.kind`。

最小例子（拟用，尚未注册）：

```ts
const id = 'dsh-plugin-hallmark/session-components';
const kind = 'hallmark-components';
// disposer由插件effect或slots.inject持有
sidebarRightTabs.register({ id, kind, title: () => '本会话组件' });
slots.inject('sidebar.right.pane.tab', () => slots.register({name:'sidebar.right.pane.tab',key:id}, SessionComponents));
slots.inject('sidebar.right.pane.tab.title', () => slots.register({name:'sidebar.right.pane.tab.title',key:id}, SessionComponentsTitle));
sidebarRight.openTab(kind, {params:{viewId}});
```

不能直接占 `rightbar` / `rightbar.session` single 槽：其现有 occupant 拥有布局、Session adoption、dock store 和子 Slot 声明，替换它会破坏原右栏。

仅注册 Slot 不会产生可打开的新 TabType；仅注册 TabType 而不注册 body/title则无完整内容。所有注册必须清理，native `slots.inject` callback 返回 disposer 或 disposer iterable，不能 void。

### 1.2 Session 标准 props 与 tab hook

声明 [9154–9162](../../test/spike/evidence/dsh/node_modules/@deepseek-ai/dsh-client-ui-sidebar-right/lib/client.js#L9154-L9162)：两个槽都是 keyed/session，注入标准 hook `tabInfo`。组件取**标准 props.sessionId**，不要用根当前 mainView 缓存代替该 Tab 所属 session。

`useTabInfo()` 的实际形状源 [8964–8987](../../test/spike/evidence/dsh/node_modules/@deepseek-ai/dsh-client-ui-sidebar-right/lib/client.js#L8964-L8987)：

```ts
{
  sidebar: {expanded, fullscreen},
  panel: {id},
  tab: {
    ...tabRecord,
    visible,
    navigation,
    signal,
    actions,
    refreshShortcut,
  }
}
```

- `tab.navigation.params` 承载本插件打开 Tab 时明确给出的 viewId；strict string 校验，不猜 `block.result` / dataset 店铺等字段。
- `tab.signal` 是 native occurrence 生命周期；请求将它与本组件 AbortController 合并，卸载/关闭不得晚写错 Session 状态。
- `tab.actions.openTab/openResource` 是 public hook action，并已绑定该 tab 的 Session，源 [6162–6172](../../test/spike/evidence/dsh/node_modules/@deepseek-ai/dsh-client-ui-sidebar-right/lib/client.js#L6162-L6172)。适合“本会话组件列表 → 打开具体组件”。
- `tab.actions.bindCommands({refresh?})` 是 occurrence-scoped注册，返回 disposer；需要按 live SDK 确认 command签名后再接入，不重放业务写。
- 可采用同一个单实例 kind + params 切换当前 view，native `multiple:true` 会每次生成唯一 page address，若需要“列表和各组件多标签”再用第二个独立 view kind或精确资源地址；MVP不靠反复随机开 tab 模拟已确认业务。

### 1.3 工具结果卡“打开右栏”不得跨会话

现有输出 meta [render.ts](../../packages/dsh-plugin/server/render.ts#L12-L16) 为 `{hallmark:{status,viewId?}}`；ToolViewProps 标准 sessionId 与这个 viewId 组合是本会话结果引用，不从模型 args 信任 sessionId，也不从 JSON 文本猜字段。

`sidebarRight.openTab` 在 [6394–6396](../../test/spike/evidence/dsh/node_modules/@deepseek-ai/dsh-client-ui-sidebar-right/lib/client.js#L6394-L6396) 使用 `require()` 的 **on-screen Session**。因此工具卡按钮必须确认 `sidebarRight.mounted.getSnapshot() === props.sessionId` 才调用全局 openTab；不等则提示切回对应聊天，不能把 B 历史组件打开到当前 A 的右栏。

源码 `openTabIn` / `openResourceIn` 明确是 controller内部 TabDomain路径、不是 ISidebarRight public API；不能直接调用来绕过上述条件。右栏内部使用框架给的 bound `tab.actions` 即可正确定位。

### 1.4 可达入口

- 工具结果卡新增“在右栏打开”，不是自动导航或自动激活应用。
- 普通聊天中可加 `conversation.input.left` list/session 的独立 id 按钮“本会话组件”，或在 TabDefinition.guide贡献新 guide capsule；均不占原 single。
- guide 的公开源码形状包括 `{id,order,title:()=>string,description?:()=>string,icon?}`，registry自动补 kind/providerId；仍需 Lead exact SDK确认后使用。
- 右栏 view完整交互复用现有 ViewRenderer/SnapshotView（分页、排序、筛选、只读刷新、设计/明确保存），只消费真实已获取快照。没有数据就空态/缺失，不把参考图“32商品/5低库存”抄成数据。
- “在工作区打开”委托已存在的应用 Workbench tabs行为与公开 `layout.selectPanel`，不新增 DSH Workspace/Tab Service、不伪造新聊天。原生 `uiWorkspace.openSession` 只用于用户明确进入已有聊天，不用于开组件。

## 2. 当前后端缺口：临时组件尚无 Session owner

当前 [PresentationManager](../../packages/presentation/src/index.ts#L18-L49) 的 `#temporary` 为整个 service的 Map<ViewId,Spec>；[ViewSpec 类型](../../packages/presentation/src/types.ts#L13)没有 session owner；core render/update目前直接保存返回viewId。

因此：`/ui/saved` 是用户 profile明确保存的配置，不是当前会话的临时组件；`/ui/views/:id` 是 Workbench显示 authority，不可作为本会话列表证据。不能扫描全部 global views 后贴“本会话”标题。

### 2.1 最小 owner投影：Lead决定使用内存索引（待实现/验收）

独立服务在成功 `hallmark_render_view` 时，从可信 `InvocationContext.sessionId` 写 **仅内存** 的 `session_views` 索引。它与临时Spec生命周期相同，不写SQLite，不另存Spec，不保存entry/template：

```ts
{viewId, sessionId, title, createdAt, updatedAt, origin:'agent'}
```

- 服务先检查 viewId是否已经归另一个session所有，禁止通过手写spec.id抢占。
- `hallmark_update_view` 检查 owner相等才更新投影，不允许猜另一会话viewId来认领。明确共享saved design编辑走Workbench authority，不混淆为本会话agent生成结果。
- 不创建常用入口、不自动saveComponent；投影记录只表示来源与所属。
- service重启时临时Spec与owner内存索引共同丢失，本会话列表为空；旧viewId读取应明确提示“不存在或临时组件已过期”。不能区别未生成/已过期就不能伪造历史owner，也不得拿同名saved/global视图顶替。此行为是临时结果过期，不是未授权保存后的自动恢复。
- 旧版无owner临时视图不自动归当前会话。如果要恢复旧聊天，须按已核实DSH Session ToolResult日志按session解析meta证明来源，不扫描profile视图猜测；MVP可明确只列新流程生成的结果。

### 2.2 拟定只读接口

服务Bearer保护：

- `GET /sessions/:id/views` → `{sessionId,views:[{viewId,title,createdAt,updatedAt,state:'ready'|'expired'}]}`。
- `GET /sessions/:id/views/:viewId` → owner匹配的真实ViewSpec。
- `GET /sessions/:id/views/:viewId/data` → owner匹配的ToolResult<ViewData>。

Host认证桥可新增 resources `sessionViews/sessionView/sessionViewData`，明确sessionId、viewId，沿用 `knownSession` 的 live/persisted验证。不要求聊天应用active（用户关闭能力后仍能看自己的只读历史），但必须owner匹配，不走agent业务工具，不触发采集/上品/价格/库存写。

列表和DTO仅投影真实数据：0条可呈空态；不引用全部profile/components，也不把用户未明确保存的结果当常用入口。

### 2.3 逐条缺口/验收矩阵（Lead实现后更新证据）

| 项 | 最小验收标准 | 本次状态/不允许的替代 |
|---|---|---|
| Native render归属 | trusted session A成功render才生成A→viewId索引；B列表无该id | 需要Lead core实现，不能由UI params自己认领 |

## 3. 现场/运行边界

本次仅契约与源码审查，不改 core/frame/chat/profile，不写客户端或后端正式新代码，不主动跳聊天。新右栏注册和新增owner endpoints尚未实现/验证。

0.1.3 Host adapter的 `app_info.hostPluginVersion` 才是加载证据的一部分；manager inventory version不等于正在执行版本。当前 installation出现restart-required/rootInclude错误，应保持明确“代码已开发、现场未加载”，不能以本设计或合成测试改写成已通过。
