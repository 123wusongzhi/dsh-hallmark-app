## 交付目标

1. 三个采集能力：搜索、默认精简资料、依据/图片读取。规范模型可更换采集提供者，关键词不搜索旧任务；结构与完整性明确，图片直接可查看。
2. 上品准备入口：组合所选 SKU、采购关联、规则、包装、店铺关系与可得类目资料；不新增声明、审核步骤或重复 facts。
3. SKU 包装维护：商品单组默认共用，专属/人工值覆盖；组合重量按数量求和，尺寸复用，null 才提问；用户可通过表格维护。
4. 草稿、定价、审核执行使用同一规范资料；兼容既有工具和已保存组件，接通新采集读取，保留历史与原请求身份。
5. 真实验收：两款商品各 5–7 个 SKU。制作来源真实、俄语可读、规格对应的标题、属性、主图/详情；实际提交 bill，核查导入、审核与可售状态，分别报告，不把已发送当已上架。
6. 会话证据：记录真实准备/资源/草稿/提交调用。区分一次性开发调试与正常上品会话，统计资料字节和调用次数，不把内部程序查询算成 Agent 反复取数，不宣称未测 token 数。

## 实施次序

### 1. 确认接线和冻结契约
读取必要源码，列出现有工具、数据与持久化接点；保留已有工作树。固定采集规范模型、包装仓储接口，记录来源原值和明确单位。

### 2. 并行实现独立模块
- 采集模块：来源规范化、精简投影、分页、精确 SKU、原始依据与素材资源。
- 包装模块：规则、覆盖记录与单/组合计算。
- 维护界面：现有经营设置中的 SKU 包装表，复用原 Host 传输。
- 主任务负责统一能力注册、prepare、经营读取、SDK/skill、迁移接入、最终安装与真实上品。

各执行者仅修改明确负责的文件；不覆盖或撤销其他任务的修改。完成契约后同步接口，避免同文件并行改动。

### 3. 验证数据与经营行为
有意义的固定样本覆盖：共享包装、SKU 专属与人工覆盖、组合重量/尺寸、null、335 SKU 分页、搜索噪音、单位、图片关联、旧调用兼容；验证准备和提交同源、成功行不重发。

### 4. 打包与 DSH 安装
使用现有发布流程；安装前保存运行状态和业务数据，确认没有其他活跃写入。保留回滚包，检查实际运行版本、规则、店铺与已有记录未丢。

### 5. DSH 内真实 Agent 的 bill 验收
用户明确补充：必须由 DSH 环境内的 Agent 在真实会话执行；Codex 外部编写内容、生成图片或脚本代调提交均不算这一项验收。代码开发与安装仍在项目内进行。DSH 会话使用安装后的工具和 skill，自己调用 prepare、读取必要素材、制作标题/属性/图片/详情，再通过统一 submit 提交；记录宿主实际工具事件及平台结果。这里早先生成的图片仅为开发尝试，不交给验收会话冒充其成果。

选定两款来源商品：绳头尾扣（6 SKU）与碗盘架（5 SKU）；精确来源身份仅留本机证据。两款已有 bill 同款；采用独立验收货号，复用精确采购 SKU 的已有包装申报，明确保留与原货号的区别。未提供真实库存时不编造库存，不将导入完成等同可售。决策模型通过 OpenRouter 使用 openai/gpt-6-luna-decisions；密钥不输出。真实失败按字段修正，未知请求先核查原请求。

### 6. 交付证据
提交实现说明、相关测试、实际版本、逐 SKU Ozon 结果、图片与内容样例、真实工具会话轨迹、遗留事项。保留生产上架结果供用户使用，不擅自清理或下架已验收商品。

## 范围说明
本次不建设 MySQL 采集应用或重写采集器；旧采集箱仍可作为数据提供者。独立化目标是统一数据接口与经营调用脱离旧任务/费率依赖。所有兼容依赖逐项核查并给出已迁/剩余状态，不把接口封装等同于数据已搬迁。
