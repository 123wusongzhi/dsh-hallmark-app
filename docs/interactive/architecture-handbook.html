为什么能少读很多

已知噪音不进默认返回：重复表单、可选值字典、多语言重复和旧任务明细。 实际属性值与原始依据保留。Agent 可以追查，不依赖有损模型摘要。

有选择就不再搜索。prepare 组合资料，不增加审批或重复 facts。

类目未定时返回候选，选定后再读该类目的必填字段。

SKU、包装与利润：程序直接处理

规则 程序如何做
商品只有一组包装 默认全部 SKU 共用
单 SKU 用户维护 → SKU 来源 → 商品共用 → null
多件或多 SKU 成员重量 × 数量后相加
组合尺寸 用户维护或组合已有值优先，否则复用成员已有完整尺寸
多组尺寸可选 默认按保存的组成顺序取第一组，可在表格覆盖
规则无结果 按字段返回 null；不填零，不清空其他有效值

不要求重新测量，不新增包装审核，不让 Agent 再判断规则是否合理。

用户维护表展示：商品/SKU、组成数量、长宽高、重量、取值方式和缺项。 人工覆盖不被同步抹掉。清除覆盖后恢复自动规则。

审核与异常：只在关键位置处理

事情 谁负责 Agent 要做什么
身份、采购组成、成本、公式、范围、重复请求 程序 使用结果，解决明确缺项
包装共用、叠加、尺寸复用 程序规则 有值继续；null 才问
标题、图片、件数和属性含义 独立决策模型 根据具体意见修改实际成品
决策模型不可用 Host 的独立模型子代理 无需主 Agent 自己宣布通过
Ozon 字段拒绝 平台 + 错误翻译 看哪个字段、原因、怎么改
限流、处理中、未知写入结果 后台执行程序 按原请求查看，不换身份重发
关键事实或经营意图无法确定 用户 Agent 只问具体问题

决策模型沿用 OpenRouter 的 openai/gpt-6-luna-decisions。 服务端读取环境变量 openrouter；工具、页面和 Agent 上下文不返回密钥。

机械检查能补全就自动补全；Ozon 自己校验的内容不在本地再建一套。 没有“我看过了”的声明、双录 facts、强制重复回读或固定等待 60 秒。

同一内容问题首次退回后，允许两次实际修改尝试，再决定是否升级。 技术等待不消耗修改次数。修改共享内容时，程序识别受影响的销售行。

三种状态要分开

已发送、已导入、已上架不是同一件事。 程序和 Agent 只汇报已经取得依据的状态。

阶段 内容 对旧平台的关系
已有基础 独立店铺凭据、Ozon 请求、经营规则、动态利润、草稿及审核执行 部分准备过程仍读旧采购详情

本次迁出 历史采购关联、旧费率参考、旧回执与经营启动依赖 在当前插件保存，日常经营逐步独立
以后完成 DSH 独立采集应用、MySQL、采集管理界面与数据素材搬迁 最终替换旧采集提供者

旧原始读取入口留作显式追查。新 Agent 默认用新能力。 旧表格需要的结构由兼容层保留，结构变更同时升级契约和调用方。

采集资料暂留旧平台期间，还不能宣称彻底关闭旧平台。 同一数据源搬家保留商品、SKU、素材身份与历史关联。

执行次序与验收：怎样算真正做完

  1. 01固定资料与接口统一身份、字段含义、默认返回与继续读取方式
  2. 02接入旧采集箱来源映射、搜索去噪、SKU 分页、图片直接查看
  3. 03接入经营准备prepare 组合店铺、类目、包装和规则
  4. 04做维护表与多 SKU单 SKU、组合 SKU、人工覆盖与 null 分支
  5. 05接通原经营流程草稿、审核、执行、部分失败与旧调用迁移
  6. 06验证并安装按真实调用检查资料、成品、回执与 DSH 使用
