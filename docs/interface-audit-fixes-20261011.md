# 接口可用性审计后的修复

## 与 849cf91 的关系

849cf91 修的是原始资料读取、准备流程与提交恢复，没有修复本轮独立复现的实重路由、错误详情、inspect 错误呈现、会话绑定提示、SKU 占位身份、输入契约缺口。本轮在 15b81a4（生产代码等同 849cf91）上修复这些问题。

## 改动

1. **独立经营实重读取。** 已配置经营连接的店铺使用 Ozon 报告创建、查询及下载，不再访问旧 4281。持久化 intent/code，按连接、配置版本、店铺、凭据版本和日期隔离；等待中、重启及并发重用同一报告。未知创建结果不自动重发；明确限流和报告失败有重试等待。迟到的等待/失败不能覆盖完成状态。仅解析可核实的单 SKU 单件包裹，报告 URL、客户列和内部编号不进入 Agent 结果。
2. **准确传递私有报告编号。** 真实验证发现报告 code 包含 Client-Id，旧通用脱敏器会改写它，继而触发查询 404。新增固定的内部报告请求方法，保留完整 opaque code；公开响应继续隐藏编号、签名地址与凭据。没有添加猜测或反脱敏的生产恢复逻辑。
3. **完整读取取消与报告到期。** weights 的完整快照读取传递取消信号；单个调用取消不影响其他等待者，最后一个取消才终止读取，迟到结果不保存为成功。查询标识固定一小时到期，不因持续刷新无限续期；保持其他数据源和后台刷新语义。
4. **平台错误详情。** Provider 保留受大小限制、脱敏后的 HTTP 状态和平台字段诊断。空 products.info 查询在本地指出缺少商品标识，不再用空请求试探平台；有效查询被平台拒绝时仍能看到修正依据。
5. **inspect 错误不再被遮盖。** 不存在 operationId 的明确错误直接返回，不再请求不存在的模型投影记录。描述明确区分 operation.operationId、invocationId 和 resultRef；正常操作和真实投影故障继续走原路径。
6. **子代理绑定提示。** 明确区分“未绑定/未启用”和“有多个连接待选择”，不再反复要求补一个已经传入的 connectionId。显式宿主绑定后可读。没有可信通用父子委派接口，因此没有自动继承父会话权限；仍由宿主明确授权或父会话读取资料后转交。
7. **无效平台 SKU。** 0、负数、小数、前导零等转为 null，覆盖当前响应及旧完整快照/游标/compose 缓存。保留有效大整数字符串精度、productId、offerId、平台状态和原始缓存，不改变采集源 SKU。
8. **输入契约和 SDK。** 明确采集选择、类目各模式字段、调价/库存目标、旧上品 offer_id 与采购 SKU 关联。保留批量续读、店铺别名和合法旧采购关联方式。生成 SDK 保留组合 schema 的同层字段和 required 分支，不再退化为宽泛 JsonValue；同步生成类型、工具定义与文档。

没有删除兼容入口，没有把平台未知更新时间填成当前时间，也没有改变已存在的大结果分段读取机制。

## 真实验证

同原会话的 Bill 店铺、2026-10-09 至 2026-10-09、limit=1：

- 修前：4281 无监听，连续两次 ECONNREFUSED，被封装成 HALLMARK_UNAVAILABLE。
- 新链路第一次：创建报告 HTTP 200；发现通用脱敏改写 code 导致 info 404，并据此补真实格式的回归测试。
- 修复私有编号路径后：继续查询同一份已创建报告，info HTTP 200、下载 HTTP 200，最终 ok。该日期没有符合单 SKU 单件条件的实重记录，不能声称验证了非空真实重量值。
- 再次读取：ok，无新增网络请求。
- 真实验证仅允许报告 create/info/download；没有商品上架、调价、库存写入。凭据只由现有 Gateway 在进程内部读取，报告状态使用独立测试库，生产业务库和连接配置未修改。
- 为继续同一份测试报告，仅在隔离测试库中恢复了本次已知被脱敏器改写的编号，没有重复创建报告。这是一次性测试恢复，不是应用行为。
