# 新增经营动作：批次刷新时保留输入

## 已复现的问题

基线 `d4ec107` 的真实 React 经营操作组件允许用户在“添加经营动作”填入销售货号和目标售价后点击“刷新批次”。当受控列表回执不再包含当前批次时，自动选中另一批次，导致按批次标识挂载的新增表单重建，未保存输入丢失。隐藏再显示页签也会触发列表重读。此前手动切换批次的放弃确认不能覆盖此路径。

复现使用真实业务引擎创建的本地批次，以及已记录商品、店铺快照作为基础。列表缺失、空列表、失败及延迟回执是明确的本地控制场景，不是商家线上事故证据。未访问商家网络或执行真实商家写入。

## 候选行为

- 新增表单有输入时，列表刷新保留原选择及表单，包括尚未选择任何已存批次的新建表单；不自动转移到其他批次。
- 原批次暂不可读取时显示明确提示和占位选项，保留输入并禁止添加。用户可刷新重试，原批次恢复后继续添加；也可通过已有确认明确放弃输入并切换。
- 未修改或净零输入仍沿用原有自动默认选择。手动切换、取消确认及明确放弃不被额外阻塞。
- 新增提交使用当前已提交渲染的许可。列表重读、缺失结果、切换和隐藏退役旧提交回调；不会因为调用此前捕获的表单回调而向旧批次写入。
- 会话、店铺身份仍隔离。旧读取回执不恢复已放弃输入，不携带输入进入另一身份；没有新增跨身份缓存或自动保存。

生产改动仅 `packages/plugin-apps/client/business-operations.tsx`。新增 `test/plugin-apps/business-new-form-refresh.test.ts` 并登记真实数据分类。初版 `c3f8aea` 独立检查发现捕获的旧表单提交仍可调用旧回调；`4f71053` 增加提交许可，`18579e0` 增加恢复后真实保存的正向控制。

## 验证范围

新增三项真实 React 与本地引擎测试覆盖：

1. 缺失、重复空列表、失败及恢复；保留货号与售价；取消与明确放弃；新建表单刷新；隐藏再显示；会话与店铺隔离；迟到回执和旧提交回调。
2. 未修改、净零输入及空列表的负向控制，验证原有正常自动选择仍可用。
3. 原批次恢复后的启用提交调用真实引擎 revise 一次；明确放弃并新建后的启用提交调用真实引擎 create 一次。两者均不调用外部执行或审核，避免保护机制锁死正常保存。

最终三用例使用 Node 24.21.0 在构建时替换基线生产组件：2 项失败、1 项正常回退负向控制通过；候选三项全部通过。独立只读评审重跑候选与原导航测试，Node 22.18.0 和 24.21.0 各 4/4 通过，并独立确认旧提交回调已退役，当前启用的保存仍可执行。

最终候选 `18579e0` 的经营操作与上品编辑定向组合（`business-*.test.ts` 及 `listing-draft-editor.test.ts`）在 Node 22.18.0 / 24.21.0 各发现 51 项：50 通过、0 失败、1 跳过。跳过项为已有的 Windows PowerShell 技能安装测试；Linux 下按原测试声明跳过。两版本 `tsc --noEmit` 与真实数据分类审计均通过，审计 329 个测试文件。首次在新工作树生成浏览器快照前的类型检查缺少 browser-data；准备数据后重跑通过。

最终基线替换仅在测试构建中执行，不改变最终生产文件。原始日志仅本地保留，未随本说明提交。

## 边界

这是挂载期间的输入连续性保护，不是持久保存。整个组件卸载、浏览器硬刷新或进程退出仍可能清除新增输入。没有新建自动恢复系统、自动业务写入、安装、部署或发布。测试不等于浏览器视觉验收、Native/DSH 宿主联调、线上商家验证或全仓测试。
