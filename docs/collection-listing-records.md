# 采集箱：按上品记录选品

面向新上品选品，使用 `hallmark.collection.search` 的 `store.listingRecord`，并指定目标店铺。程序自动读取经营记录并刷新需要更新的状态，Agent 不需要先查询全店商品或轮流尝试旧筛选。

| 返回值 | 含义 | 使用方式 |
| --- | --- | --- |
| `not_found` | 本次记录查询已完成，本店没有该采集商品的精确关联或已保存上品行 | 作为新上品候选，进入 `hallmark.listing.prepare` |
| `found` | 本店存在精确销售关联或已保存上品行 | 看现有草稿或销售状态，避免重复建立 |
| `unavailable` | 查询未完成、过期、失败或数据来源不匹配 | 不推断为空；读取结果中的统一原因 |

“无记录”不承诺历史上绝对没有同款。部分历史店铺商品尚未建立采购关联时，结果顶层给出一次说明，不影响其他商品按本地记录成为候选。

## Agent 调用

```json
{
  "source": "alibaba_com",
  "store": {"id": "目标店铺 ID", "listingRecord": "not_found"},
  "limit": 30
}
```

`source` 使用当前采集箱实际返回的来源标识；可省略。关键词仍然只匹配商品事实。

`recordLookup.status=complete` 且 `total=0` 表示真正没有符合条件的结果。对于 `found` / `not_found` 筛选，若仍有商品记录不可查，则 `total=null`，`recordLookup.knownMatches` 给出已知匹配数，`unavailableItems` 和 `reasonCodes` 说明未完成部分。已知候选仍正常返回和分页；分页结束不代表未知部分已查清。来源、类目统计只统计已知匹配项。

## 销售状态保持独立

- 归档、发布失败、审核处理中、无库存都不会抹去记录。
- 保存草稿算有记录，不代表 Ozon 已经创建商品。
- 同一来源商品只在另一个店铺有记录，不影响当前店铺判断。
- 组合上品行的每个采购成员都计入对应来源商品的记录。
- 上品准备结果同时提供记录摘要。保存的上品行可通过 `hallmark.plan.list` 查看；原有销售 SKU 关联继续保留。

旧 `store.status` 和 `store.association` 的含义保持不变，供已有调用方继续使用。新选品入口不再推荐它们来表达“本店无上品记录”。

## 表格

采集商品表提供目标店铺和上品记录筛选，使用与工具相同的字段。完整快照可筛选全部快照；分页表只筛选已加载商品，并明确标示范围。旧快照缺少新字段时显示暂不可查，刷新后取得新字段。

## 验证范围

自动测试覆盖跨店铺关联、归档、失败、草稿、组合采购成员、未关联历史商品、同步失败、初次历史迁入失败及恢复、分页和统计、真实零结果、表格切换筛选与范围提示。此变更不增加上品审核步骤。
