# 素材库关闭：保护尚未保存的组件配置

本文记录累计十项修复之后的候选独立验证过程，独立验证代码基线为 `069817a535769add648295f88086132768e39b00`。后续整合源码 `2d3f67005f7dfee006c2bf942a8154723b26c9a0` 的双版本70文件组合结果见[Material关闭保护双Node整合回归](testing/material-close-dual-node-20261016.md)。独立验证与组合验证均不包含真实商家写入，也不等于完整全仓测试。

## 修复行为

- 在素材库/配置组件中编辑名称、显示列、字段、布局或数据来源后，Workspace 的关闭按钮先显示局部“继续编辑 / 放弃并关闭”。继续编辑不写入、不丢草稿；明确放弃才卸载。
- 提示位于可见 Workspace 区域。素材库标签隐藏时关闭仍能看到提示；取消不强制跳转，当前任务保持不变。
- 浏览模板、未修改、有效净零变化、成功保存后关闭没有多余确认。信息选择面板自身的取消/返回/关闭仍按原规则放弃尚未应用的选择；已“应用并预览”的配置变化属于需要保护的未保存内容。
- 保存请求 pending 时阻止关闭，以及会卸载该编辑器的配置目标替换/应用切换。其它工作区标签、回聊天不受阻；目录/预览读取 pending 不锁关闭或应用选择。
- 明确失败回执保留草稿及可见错误。成功回执以“请求快照、当前编辑、服务器返回”三方对照合并，接纳数据源注册后的 revision/ref 规范化，不吞请求发出后的新编辑，也不让旧回执弄脏新选择的模板。
- 不自动保存、不新增全局 confirm、不承诺关闭会取消已发送的保存。

## 实现范围

生产文件仅三个：

1. `packages/plugin-apps/client/material-library.tsx`：语义配置基线、局部关闭动作、保存状态、自动默认变更及保存回执三方合并。
2. `packages/plugin-apps/client/workspace.tsx`：可见关闭提示、关闭请求、pending 防编辑器替换。
3. `packages/plugin-apps/client/directory.tsx`：默认关闭的可选 `appSelectionDisabled`，仅真实素材保存 pending 时禁用实际应用选择按钮并同步检查，避免内部 selected 先改变后延迟卸载。

语义比较复用 `configuredColumns` / `withDisplayColumns` 的有效列规范，统一默认密度/页数、有效名称及数据源输入默认值；忽略生成的实例 ID 和界面浏览状态。请求后的编辑通过三方合并保留。没有引入跨应用持久草稿系统。

测试新增 `test/plugin-apps/material-close-draft.test.ts`，并更新旧 workspace-tab-close 测试中的隔离素材库替身，使其响应新的关闭请求协议；真实组件回归无替身。测试数据分类为字段定义、空数据封套及 transport receipt 控制，不声称商家数据真实性。

## 明确边界

- 防护针对当前挂载 Workspace 的素材库关闭及保存中编辑身份替换。硬刷新、浏览器/宿主进程退出、整个 Workspace 被外部强制卸载不保证草稿保留；这不是持久自动保存。
- 普通未保存状态下切另一模板/配置另一实例/应用的既有行为未扩为通用保护系统；本批只有保存 pending 防实际卸载。
- Host→Runtime 的 workbench transport 已有 `APPS_DATA_REQUEST_TIMEOUT_MS=150000`（150 秒）；浏览器到本地 Host 的素材保存 fetch 未单设 deadline，也没有素材保存未知结果检查 UI。因此完全不 settle 的请求仍会保持关闭/换应用锁，但可切其它标签或回聊天。没有用定时解锁伪装请求已经取消。
- timeout/network 错误只说明回执未获得，不保证服务端未保存；本批保留当前草稿，不增加自动重发、未知结果轮询或持久恢复机制。

## 追加复核：迟到成功不得抢回工作台

追加复核发现首个提交 `0a22911` 仍继承旧 `onComplete` 的无条件 `setLocalTab('workbench')`。原关闭 guard 没有解决这个场景，不能以之前的验证作覆盖证明。

已新增两项正式真实 React 用例，先在 `0a22911` 上均复现失败：

1. 保存挂起 → 进入“经营设置” → 成功：保持经营设置选中，同时正确应用工作台元数据更新；应用面板隐藏期间成功也不改原素材页选择。
2. 旧完成回调 → 新编辑器/另一应用：不导航新编辑器，不把 Hallmark board 注入 Notes。仍属当前 app 的元数据通过已有 revision-aware `acceptWorkbench` 接收。

追加生产改动仅 `workspace.tsx`：按 app/session/编辑实例/打开状态建立 owner token，只有仍是原 owner、当前 localTab 为 materials 且应用页可见时才按原流程导航。当前页已离开则保持当前任务；元数据更新与导航分开判断。

追加验证：两用例红→绿；累计新增14项，双 Node 七文件小回归各27/27，类型检查及321文件分类审计通过。追加证据使用 `navigation-*` 日志；上述永久 pending、未知结果、硬刷新及进程退出边界不变，不声称已解决独立的超时恢复问题。

## 追加收紧：避免无关 UI 变化重复构造语义键

下列优化前后对比仅针对本轮当时尚未发布的关闭保护候选实现，不代表已发布基线存在额外14次计算。真实 MaterialLibrary 计数探针在测试 bundle 内仅为 `materialConfigurationKey` 插入调用计数器，未给生产加入计数器。相同七次纯 UI 变化（搜索三次、分类两次、调整面板进出两次）：

- 本轮保护候选、memo优化前：18 → 32，额外14次完整语义键计算。
- 同一保护候选、memo优化后：6 → 6，额外0次。
- 真实名称编辑：6 → 7，仅重新计算 draft 键；关闭提示/继续编辑不再重新计算。
- 新目录 sources 对象：7 → 9，draft/baseline 两键都失效；dirty 仍保护真实修改。
- 确认保存：9 → 11，新 baseline/规范化内容重新计算，随后可无提示关闭。

生产仅为 draft/sources 与 baseline 对象/sources 两个键分别加 `useMemo`，没有全局缓存、简化比较或跳过来源变更。自动默认、注册回执、请求后编辑继续由原语义比较和三方合并处理。这里仅报告调用次数，不声称实测页面提速。

新增一项正式计数回归，累计新增15项。最终双 Node 七文件回归各28/28，类型检查与321文件分类审计通过；追加证据为 `key-count-*` 和 `memo-*`。
