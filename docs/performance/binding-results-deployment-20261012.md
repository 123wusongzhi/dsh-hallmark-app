## 功能与性能验证

正式比较使用 90 个独立进程、950 条观测、95 组场景，全部定义内结果等价，0 个检查问题。严格分页兼容比较 860 组通过。候选最终完整测试为 1965 项：1964 通过，1 项因随机监听端口落在 Windows 排除范围失败；保留原始失败后，不修改该测试定向重跑 1/1 通过。类型检查、插件构建及应用包构建通过。

大数组全文读取耗时降低约 14%–33%；2048 SKU 的半选、全选和三商品半选降低约 29%–39%。显式宽字段读取降低约 98%，但不能默认用于窄行；短文本 literal 更慢，仍只作为显式可选能力。

5,000 商品刷新在正式五轮中稳定增加约 309 ms（6.4%）。追加一对带阶段/GC 记录的诊断显示双方业务结果和工作量相同，主要耗时来自共同的 provider_records 全表读取；该对候选耗时较低，但不能据此撤销正式负控或断言旧差异由 GC 导致。保留完整负控，未将 collection 作为新增收益宣传。

这些是隔离合成测试的条件性收益，不是浏览器帧率、真实平台网络或 LLM 会话总时长的测量。camelCase 类目 ID 规范化、Unicode 码点长度边界、错误完整性检查以及新增可选续读的行为修正已在主报告逐项列出。

## 安装和数据保持

用户确认退出 DSH 后，确认 Desktop/Host 已消失，仅停止身份、创建时间、端口归属均核实的残留闲置 Runtime。安装前完成 SQLite 一致性备份和完整性检查，复制并核对所有会话与技能。官方 Desktop CLI 使用本地安装包更新同名插件，保留回滚包，不执行数据库迁移；已有自定义技能没有被包内技能覆盖。

后台重启后只读验证通过：

- 232 个原会话文件、86 个技能文件散列均保持。
- 6 个保存组件及相关 5 张表保持；Host、Runtime 和数据库的保存目录一致。
- 1,326 条 `business_*` 业务记录保持，包括原始 JSON 和时间字段。
- 连接配置、服务密钥文件和 Schema 4 迁移记录字节保持；报告不包含其内容。
- 字典 `lastValueId` 已出现在运行中 values 模式的契约，未泄漏到其他模式。
- 其他 4 个直接插件依赖不变；Cordis 两个配置及工作区配置字节保持。锁文件仅变更本插件的本地包定位，其余 25 条包及快照内容相等。

验证未执行上架、采购或其他平台业务动作，也未使用 computer-use。Desktop 启动及进程核验均在后台进行。
