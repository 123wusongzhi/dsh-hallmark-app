## 本地修正与 15b 历史代价

### 保持正常采购选择行为

附件诊断实现把严格的“可推荐 ID”集合误用为旧选择有效性的判据，导致原来支持的数字 ID（例如原值 7、显式选择字符串 "7"）以及带空白但精确匹配的 ID 被阻断。修正后仍用旧的原始查找语义判断显式选择，只有可精确查回且唯一的规范 ID 才进入建议；碰撞、不存在或致命来源错误仍阻断。

### 保持正常 describe 交互

附件原实现会提前拆分未超原预算的 Schema，使需要完整 outputSchema 的正常任务多一次读取。本地改为规范化完整响应不超过 16384 字节时保留原形状，16385 字节起才使用可恢复拆分。正常 Notes / 小描述 / 普通描述的请求响应内容与调用次数保持；大描述恢复属于解决原失败，不能将基线失败时更少的字节认定为更快的成功任务。

15b 历史测量中，gateway 描述从 2367 增为 3476 UTF-8 字节，增加 **1109 字节**；最新 92b 的对应实测为 2463→3584、增加 1121，见前文。这是整批 fields/literal 等能力入口的成本，不单独归因于 Schema 修复，也不是 token 数。正常任务即使请求响应字节相同，也不能据此声称整个会话初始化成本完全不变。

### 消除正常采购额外诊断开销

候选原先在正常选择上也先建立规范候选及包装图库诊断。本地改为实际存在无效选择、且仍有诊断预算时才构建。256 个 SKU、512 张图片的定向 create→submit 观测中，额外包装图库访问由 2 次降为 0 次；这是直接访问次数证据，不冒充完整任务耗时百分比。

### 补齐超长 rowIds 的完整续读

简单溢出回读原结果只能恢复当前提供者页，可能丢掉剩余选中行。本地同时保存当前页的只读入口及带完整 rowIds 的下一页调用，用有界字符串分页恢复这两个入口；随后再读取最新下一页，不重放原业务动作。

新增控制覆盖 40 个长 ID 的完整恢复、512/1024/16384 字节预算、下一页修订变化、原连接权限撤销、原结果或下一页指令保存失败。保存失败返回明确 RESULT_SPILL_FAILED，不冒称完整成功。完整测试已包含这些控制。

### 普通分页的过度序列化回退已修复

便携 parity 发现一个真实回退：对普通四键 result 根对象，budget=512、limit=100 时，基线可沿目录及字符串页完整恢复，合计 363 次读取；候选用 Number.MAX_SAFE_INTEGER 预估根本不存在的最大游标，误触发 serialized-json，变成 1162 次读取。两者原值相同，但新增 799 次读取不能作为可接受的普通页形状变化。

生产实现已收窄为实际目录/数组边界，并保持一次完整读取的模式稳定。修复后这个反例两臂都是 363 次（3 个 directory 页、360 个 string 页）、每页最多 512 字节、完整结果 SHA-256 相同；普通页形状恢复。独立生产边界测试另覆盖数组跨数字位数的游标、deferred 子项、真实引用放不下时的稳定序列化，以及原长路径/权限控制，共 16/16 通过。

更新的 reader-parity 保留原 854 组比较，再加 6 组长路径控制，共 860 组。831 组原页面字节完全相同；29 组仅在实际递归执行基线后证实原结果无法完整恢复时允许 serialized-json 分支。76 份完整恢复记录中，基线有 11 份 RESULT_PATH_BUDGET_EXCEEDED、3 份公开路径超过 4000 码点；候选全部逐页检查预算、游标前进、文本与原 JSON 码点区间，拼接后 JSON.parse 精确还原原 result 子树。基线能完整恢复的差异一律判回退；不按“小预算”笼统豁免。

因此 ten05 确实扩展了无法用普通目录恢复时的分页形式，不声称任何输入下页形状完全不变。原始失败与修复后记录分别保存在 compat/reader-parity-before.log、reader-parity-first-fixture.log、reader-parity-after-attempt2.json；早期 attempt1 也保留。这里不把基线恢复失败当成加速，不报告该正确性脚本的时间收益。

## 最终选择规则与功能变化披露

正常功能路径应维持输出、权限、选择精度和可恢复性。修正错误完成证据、错误诊断、Unicode 规范边界等行为变化单独报告；通过测试不等于所有路径输出字节完全相同。

fields 与 literal 为显式使用能力，短数据退化不能被隐藏，也不应自动应用到所有结果。namespace 为自动执行路径，本轮全命中负控稳定退化，已经决定剔除该项；混合大库收益不进入最终结论。涉及取舍的最终代码若变化，只能使用对应最终源码的受影响补测，不能直接沿用已经不同的候选结果。

不把不同场景百分比相加，不声称 20 项各有独立计时收益，不从合成工具链推断真实 agent 总耗时、tokens、业务转化或浏览器流畅度。gateway 的描述成本按对应版本单独呈现（15b +1109、最新 92b +1121 字节），不混为一个全局数值；失败/恢复指引和 setup 成本也保留。
