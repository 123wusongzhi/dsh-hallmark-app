## 已确认并修复的问题

- 证据路径解析为了判断文件是否需要迁移，会反复读取全部 provider_records（现场 2681 条、约 49 MB JSON），并在当前目录新生成的文件根本不需要迁移时，仍验证全部历史迁移证据。组件分块读取反复触发这条同步路径，阻塞 Runtime 请求处理。
- 改为按 evidence_relocations 命名空间索引查询；没有适用迁移映射的直接文件不验证无关历史清单。适用映射仍走完整清单、冲突、路径、哈希与符号链接检查。每批次与后续请求仍重新读取当前记录，不跨请求缓存授权结论。
- dataTransfer 的 getData、readBindingPage、分块 read 在响应丢失时至多重试一次，保留原始请求身份。refresh、发布及其他写操作不自动重试。
- 扩展调用区分请求取消、超时、空白/非法 JSON、连接丢失，保留 requestId、动作与尝试次数。错误消息不再断言进程退出。
- 无效扩展协议以前可能返回 200 空响应，现在返回明确的 400 INVALID_BRIDGE_MESSAGE。这是本次复现额外发现的协议缺陷，不能据此断言历史页面发出了无效协议。
