## 相对提案做的兼容性修正

只选取相关改动，没有夹带此前 #75 被拒绝的补丁、其他测试分支改动或主工作区业务修复。

- 交叉审查发现：新增隐藏暂停后，native 组件被外部关闭时，可见的工作台 fallback 仍是 inactive。已用一个可见性条件统一导航、显示与读取，并通过真实外部关闭回调的先红后绿回归验证。
- 扩大验证发现：最初新增的 Agent 提示小模块未进入 SDK 隔离打包路径，造成 32 项构建失败。最终将同一五态提示函数内联现有模块并移除新依赖，保留旧 SDK 测试和断言；以最新源码重新复测。这是本次引入并修正的兼容回归，不归咎于环境。
- 店铺重读使用现有 ref 合并同事件重复处理，没有加入提案的 500ms 冷却和测试专用调度；后续明确取消/重读可以立即执行。
- 草稿恢复仅限当前挂载组件的私有内存：最多 4 个身份、单项 256 KiB、合计 1 MiB、30 分钟。超限、淘汰、过期均提示；关闭/真正卸载/刷新/退出后不恢复，不写 localStorage 或服务端，也不建立全局池。
- 提交仍使用原 planId/expectedRevision、业务审核、幂等和未知结果恢复。保存与确认不隐式提交；同事件重复确认只提交一次，回执丢失只读检查，不重发已完成行。
- 保留既有有效业务断言；针对新的保活、确认、放弃操作更新旧测试步骤。没有 skip、放宽生产校验、重写冻结语料或通过自比较制造通过。
