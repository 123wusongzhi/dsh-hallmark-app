# Candidate.22：组件展示、预览性能与经营模板

本次提交包含 candidate.16 之后的工作区改动和 7 个经营源码模板。插件包版本为 `1.0.0-candidate.22`；模板生成器当前在仓库中使用，尚未加入安装包的 Agent 发现入口。

## 已实现

- 发布准备与独立显示尝试分离；显示失败可重新打开同一构建，处理面板隐藏、恢复和旧文档释放。
- 展示完成后更新保存控件，保存后刷新组件库。
- 按会话索引读取视图、组件摘要查询、历史按需读取；共享轮询、隐藏暂停和相同结果去重。
- 原生组件容器随可用窗口高度伸缩。
- 预览使用真实鼠标与键盘，并检查命中遮挡；外网图片通过缓存、占位及有限抽样减少等待。
- 七个只读经营模板及离线交互预览：商品总表、采集箱、利润排行、流量成交、价格复盘、促销评估、促销复盘。

## 使用记录反映的未完成项

已只读查看 DSH“实时在售商品利润组件”会话的最新交付说明。该说明记录了构建和显示确认、独立分页探针通过，但明确指出真实展示窗口未观察到分页调用。因此不能把独立探针结果当作真实桌面全量分页成功。

核对插件代码后，后续需要处理：

- `getData` 的 binding 数据不含能力调用配置，组件不能从 payload 猜 capabilityId。
- 正式预览 runner 尚未接入预览服务提供的 readOnlyCapability；预览选择附加仍是占位确认。
- 独立能力分页查询的结果不会自动成为绑定快照中的可选资源，下一页附加需要专门接通。
- 能力说明、设计技能中的部分刷新、发布和强制修改循环指引需要同步。
- inspect 可进一步汇总已确认显示版本、待显示版本和失败下一步；构建/预览回执可以用薄 CLI 编排减少手工传递。

以上属于后续方案，不计入本次实现。真实店铺数据、会话记录、Runtime 数据库、凭据和本地构建证据不随本提交发布。

## 模板边界

模板复用标准 React 源码工程与现有 SDK。预览使用示例数据；接入真实数据时需修改适配器。模板分页目前仅针对已读取数据，尚未实现服务器分页、聊天附加或跨 frame 状态恢复。详见 `templates/commerce/README.md`。
