# 产品可交付性跟进

用户目标：持续完善为商业可用插件，优先改善用户体验，自主验证。以当前代码、实际安装及运行证据判断，不以测试数或版本号代表完成。

## 顺序与完成证据

1. **刷新与分页不卡住**：真实同步完成后自动更新；同步中可读旧快照、分页；重复点击不重复同步；失败保留数据并说明原因。需要 Runtime 并发回归、真实平台分段耗时、DSH 实际操作证据。
2. **创作到展示可预测**：准备请求→单份验证计划→构建→真实预览→发布→实际展示，错误指向可执行下一步，无测试替身构建。需要一次真实 Agent 新会话轨迹及发布后的桌面证据。
3. **组件库与模板可用**：保存、即时出现、另一会话打开、编辑与历史版本清楚；失败可恢复。需要已有回归加实际桌面全流程。
4. **日常阅读体验**：窄侧栏/宽标签页响应布局，搜索分页清晰，加载时保留内容，空态与错误态可理解。根据实际界面逐项修正，避免无业务需求的额外 KPI。
5. **数据口径与规模**：采购价、实际售价、利润率准确且有口径；严格在售筛选；大列表按页读取、图片占位与缓存，历史按需读取。需要字段回归和真实规模观察。
6. **安装与维护**：构建与实际安装版本一致，可回退；入口指引与源码同步；记录已知限制。需要安装记录、重启验证及升级后使用证据。

## 后续素材与模板方向

使用可直接运行的组件素材作为基础，模板是可拆改的组合预设；允许配置字段、筛选、排序、布局、图表和模块组合。分页、刷新、图片和状态恢复由运行组件复用。常见需求经配置直接展示，新交互保留源码构建出口。优先沿用现有组件目录、绑定、模板资产和展示链路；独立讨论会话先设计，不在本轮 Web 调试中扩建平台。
