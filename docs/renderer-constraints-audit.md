**目前 Agent 能填写固定组件配置，还不能直接制作源码模板。** 主要限制来自我们自己的协议和实现。shadcn、TanStack Table 和 Recharts 的能力没有全部开放给 Agent。

本页记录现状和下一步方向。渲染协议尚未放宽；附件与组件管理已安装为插件 0.2.4。开放源码能力的具体方案见项目内 `docs/source-component-plan.md`。

## A 哪些是我们加的，哪些来自宿主

| 层次 | 当前事实 | 对 Agent 的影响 |
| --- | --- | --- |
| 自定义 ViewSpec 协议 | 固定组件、布局和属性白名单 | 只能在预设范围内组合 |
| 原生 React 渲染器 | 部分允许的属性没有实现 | 参数合法也可能看不到变化 |
| 数据服务 | 快照、查询、计算结果未完全衔接 | 有数据，也可能无法绑定显示 |
| 模板管理 | 保存配置，不保存 TSX/CSS 源码 | 不能直接导入完整开源设计 |
| Agent 反馈 | 工具返回文本和视图 ID | 不能据此判断实际视觉质量 |
| DSH 宿主 | 共享 React 18.3.1，使用宿主插件槽位 | 需要依赖兼容与接口适配 |

```callout info 核心判断
“只有 7 种组件”是我们当前的实现范围。它不是 DSH 或 shadcn 强制要求的上限。
```

## B 自由设计被哪些规则挡住

| 方面 | 当前允许 | 当前缺少 |
| --- | --- | --- |
| 组件种类 | 指标卡、表格、柱图、折线图、商品卡、状态徽标、文本 | 表单、图片墙、手风琴、独立按钮及自定义组件 |
| 布局 | grid、row、column、tabs | 自定义断点、跨行跨列、比例宽度、自由定位 |
| 原始代码 | 普通 JSON 配置 | TSX、JSX、HTML、CSS、Tailwind 源码入口 |
| 样式属性 | 少量 theme tokens | className、style、自定义 CSS、动画 |
| 数据表达 | 点分字段路径和 fieldMap | 公式、条件渲染、循环、聚合及通用状态 |
| 表格单元格 | text、currency、percent、date | 图片列、自定义单元格、行操作菜单 |
| 图片与图标 | 商品卡首行中的 HTTP(S) 图片 | 独立图像组件、图集、自选图标 |

例如，`text: "<b>商品</b>"` 只显示文字。`fieldMap` 中的 `price * 0.8` 也不会执行计算。

这些参数会被明确拒绝：`widget.style`、`className`、`html`、`jsx`、`onClick`、`actions`。

数量限制也写在协议里：单视图最多 100 个组件、100 个绑定；网格最多 12 列；JSON 深度最多 40。每个组件必须在布局中恰好出现一次。

依据：`packages/presentation/src/validation.ts:4、8、44、52、60、72`；`packages/dsh-plugin/client/render-catalog.ts:12、22、34`。

## C 为什么改颜色和排版也不一定有效

| 配置 | 原生渲染器实际表现 |
| --- | --- |
| primary、text、background、surface | 内容区域有效；外层标题和工具栏不随之完整变化 |
| mutedText、profit、loss、warning | 校验允许，但当前原生渲染器未使用 |
| fontSize.body | 根容器有效；许多子元素另有固定字号 |
| fontSize.small、fontSize.title | 校验允许，但当前原生渲染器未使用 |
| spacing | 作为布局默认 gap；不是完整的内外边距系统 |
| radius、shadow | 主要作用于组件容器；按钮和表格另有固定样式 |
| options.color、showLegend | 校验允许，但图表未使用 |
| options.description、statusField | 校验允许，但组件未使用 |

颜色只接受六位十六进制值，如 `#2563EB`。当前主题协议不接受渐变、透明色或完整明暗色阶。

图表只支持单个数值序列，最多取 50 个有效点。图表高度为 260px，颜色取统一强调色。指标卡和商品卡只读取第一条记录，不自动汇总或逐条生成卡片。

**部分视觉问题来自实现缺口。** 单靠让 Agent 更努力写设计提示词，无法让这些属性生效。

依据：`client/renderer.tsx:37、48、51、75`；`client/widgets/business-chart.tsx:7–14`；`presentation/src/validation.ts:65、83`。路径分别位于 `packages/dsh-plugin` 和 `packages` 下。

## D 截图中的利润率为什么显示横线

问题横跨数据工具和渲染器。

```flow
compute_profit -> 计算返回值: 带口径，最多返回 200 条
计算返回值 --> 可绑定数据集: 未自动建立
店铺原始快照 -> 利润字段显示检查: 不带加工口径
利润字段显示检查 -> 横线: 缺少 metricBasis
```

| 截图中的判断 | 源码核对结果 |
| --- | --- |
| 没有口径时利润字段显示横线 | 属实；缺成本也会被标为无法判断 |
| 自定义数据集键被拒绝 | 绑定允许非空键，但不会自动生成数据。给计算工具增加该参数才会被拒绝 |
| 查询式绑定不解析 | 临时查询仅生成 query 键。它没有立即执行，保存后的查询才有恢复配方 |
| 目录没有 profit，所以不存在利润能力 | 不成立。目录只列现有快照，利润路由及结果集桥接已存在 |

**当前已有可用路径：**

```flow
filter_products -> 带口径的结果集: 返回 resultSetId
带口径的结果集 -> render_view: 使用 profit-filter 模板
render_view -> 参考利润率表格: 读取 referenceProfit.margin
```

使用合成数据验证：267 条记录全部进入组件数据；0.12 显示为 12.00%；缺成本记录保持横线。该验证未调用真实商品同步或平台写入。

结果集保留 24 小时，保存组件不会延长它的寿命。长期组件还需要可恢复查询或利润快照。

下一步应接通“计算结果 → 可绑定数据”，让临时查询能读取数据。利润的来源、计算口径和缺成本状态仍应明确显示。

依据：`packages/core/src/index.ts:56、109、120、138`；`packages/core/src/refresh.ts:21、25、58`；`packages/presentation/src/index.ts:25、138、143`。

## E 交互和模板复用受哪些限制

| 能力 | 当前状态 | 缺口 |
| --- | --- | --- |
| 表格交互 | 搜索、排序、分页、勾选 | 行为写在固定组件里，Agent 不能自行设计新动作 |
| 商品选择 | 最多 100 个；附加后由用户发送 | 0.2.4 已安装原生 JSON 附件，实际交互待验收 |
| 本会话管理 | 0.2.4 已安装重命名、从本会话移除 | 保存设计保留；已打开详情会失效，实际交互待验收 |
| Tabs | 可以切换，支持键盘操作 | 只能切换配置内的固定内容 |
| 保存组件 | 保存配置、绑定和版本 | 不保存源码包或依赖 |
| 保存模板 | 保存布局、样式配置和绑定槽 | 不等于保存完整 shadcn 设计源码 |
| 模板发现 | 工作台能列内置和保存模板 | Agent 的 list_saved 只列已保存模板 |

内置模板只有店铺总览、利润筛选和操作回执三种基础配置。它们没有包含之前展示的完整 Tasks、Commerce UI 商品卡等设计。

因此，“已经安装组件库”和“Agent 能复用精美模板”之间，还缺模板接入、源码编辑和运行链路。

依据：`packages/presentation/src/design.ts:6`；`packages/presentation/src/index.ts:34、97、105`；`packages/service/src/ui.ts:24`；`packages/dsh-plugin/client/widgets/product-table.tsx:58`。

## F Agent 现在能看到自己的成品吗

**Hallmark 专用工具链目前没有视觉反馈接口。** 工具返回文本 JSON、文件引用和 viewId；它没有把实际组件截图交回 Agent。

```sequence
Agent -> 工具服务: 提交组件配置
工具服务 --> Agent: 配置已接受，返回 viewId
DSH 前端 -> 工具服务: 读取配置和数据
DSH 前端 -> DSH 前端: 渲染组件
note Agent, DSH 前端: 当前没有自动截图、布局错误和交互结果回传
```

仓库虽有浏览器测试脚本，但它们不是 Agent 可调用的视觉验证器。`renderViewHTML` 也是另一套静态渲染实现，不能代替原生 React 组件验收。

两套渲染器已发现差异：静态版本没有相同的字段映射、真实 Tabs 和交互；图表截断数量及缺成本处理也不同。因此，未来预览应使用实际运行的组件代码。

依据：`packages/dsh-plugin/server/render.ts:19–32`；`packages/contracts/src/index.ts:39`；`packages/dsh-plugin/client/snapshot.tsx:18`；`packages/presentation/src/renderer.ts`。

## G 按你确定的方向，接下来补什么

现有视觉规范作为共同标准：有颜色、有信息层级、优先复用成熟设计。该规范已加入本地与 DSH 的组件设计技能。

用户此次明确的新目标：Agent 获得原始模板制作能力，并能查看真实效果后修改。下面是待实现目标，不是当前已具备的功能。

```flow
设计规范与现成源码 -> Agent 编辑模板: React、TSX、CSS 与组件库
Agent 编辑模板 -> 编译并运行: 返回编译错误
编译并运行 -> 实际组件预览: 使用同一渲染代码
实际组件预览 -> 视觉验证器: 截图、尺寸、运行错误、交互结果
视觉验证器 -> Agent 编辑模板: 看效果，再修改
实际组件预览 -> 保存模板: 源码、依赖、资源、版本
```

| 优先顺序 | 要解决的具体问题 |
| --- | --- |
| 数据衔接 | 计算结果可绑定，临时查询可执行，长期组件可恢复 |
| 原始制作能力 | 编辑源码模板，复用完整设计，运行编译产物 |
| 视觉反馈 | 让 Agent 获得实际渲染截图、报错及交互反馈 |
| 模板管理 | 保存和编辑源码版本，让 Agent 能发现模板 |

开放设计代码时，商品 ID、数据来源和聊天归属仍要保持正确。商品选择继续遵循你已确定的方式：附加到输入区，由你确认发送。

## H 本次核验范围

审计覆盖 ViewSpec 校验、React 渲染器、数据绑定、模板保存、工具返回和宿主依赖。DSH 宿主的 React 18.3.1 已从本机安装资源核对。

利润链路使用内存数据库、模拟接口和合成记录验证。没有读取用户临时脚本中的凭据，也没有运行真实店铺修改。

本次没有取得新生成组件的原生界面截图。因此，本页给出的是源码和合成验证结论，不把工具成功或 HTML 输出当作视觉验收。

两个新增交互已完成统一验证：415 项 Node 测试、TypeScript 检查、Host/Client 构建通过。0.2.4 已官方安装并核实只读联通。原生附件的上传、移除、发送及 Agent 读取仍待实际验收。详情见项目内 `docs/release-0.2.4.md`。

后续修改应以本页和用户新要求为依据。旧 ViewSpec 白名单属于待改造现状，不应被视为永久设计边界。
