## 用户入口

在 DSH 应用区打开 Hallmark，进入固定的 **经营设置** 标签页。这里维护店铺连接、物流报价方案、上品/日常调价的目标利润，以及可选的硬性利润和价格限制。无需先选择聊天即可维护设置、测试连接、试算。经营操作和 Agent 均使用同一份已保存规则。

当前报价方式沿用已核实的旧平台口径：每销售件固定费用 + 包装重量 × 每公斤费率 + 按售价计算的佣金。可建多个方案，分别设置费用、有效期、重量范围、启停及默认方案。本轮没有虚构首重/续重、材积重或逐渠道实际报价。

| 已核实的旧平台参考值 | 新应用中用途 |
| --- | --- |
| 固定费用 3.16 元/销售件 | 方案固定成本 |
| 运费 39.3 元/kg | 重量计费，向上取分 |
| 佣金 20% | 按售价计算，向上取分 |
| 上品目标利润率 60% | 计算建议价，显式售价仍可供比较 |
| 手动 ERP 调价目标利润率 5% | 普通调价建议价 |
| 自动上品建议价上限 135 元 | 自动上品超出时提示处理，不强行截低 |
| 最低利润、一般售价上下限留空 | 原平台暂停实验的 15% 不作为全局底线 |

参考来源为原平台已发布 guide v39（2026-10-05）。方案名称为“旧平台统一参考方案”；用户可在新应用中按自己的真实渠道逐个调整。不同店铺的规则分别保存且有修订历史。

## Agent 如何上品

Agent 从旧采集入口选择原商品及 SKU，制作标题、属性、主图和详情，将实际内容与采购引用保存到经营草稿。`ozon-listing` Skill 已更新：`pricing.mode=automatic` 使用已保存方案自动定价；明确指定价格时用 `manual`。可选 `planId` 指定渠道，否则采用店铺默认方案。

`hallmark.pricing.read` 返回规则，`hallmark.pricing.quote` 从商品及采购引用取得可信成本和重量后试算。Agent 不填写虚构成本，也不重复执行程序计算。`submit` 仍是统一审核入口，规则足够时直接执行；图文语义才进入决策模型/独立审核。原有审核声明、facts 双录及重复 preflight 没有迁入。

## 数据和请求归属

- 店铺目录及凭据保存在新 Runtime。Windows 上的凭据加密主密钥由当前系统用户保护；页面和模型只得到配置状态。
- 新 Ozon 请求直接发送到 Seller API。平台写入只发一次，结果未知时保留原请求及凭据版本进行核查。
- 历史销售/采购关联第一次按原店铺身份读取并保存在本地；直接创建经营草稿也会初始化关联，不要求先打开商品列表。后续新增、组合采购关联由本应用保存。
- 采集资料仍按需从旧平台读取。历史未决回执保留原通道只读核查；启用直连不触发重发。
- 经营台账与规则采用稳定身份，修改来源连接的配置版本不会丢掉既有台账；更换采集来源后不沿用未经确认的来源 SKU。
- 旧平台计算的利润只保留为历史参考。未按新规则重新计算的成本/利润不伪装成当前数值；精确试算及经营行报价使用新规则。

## 已完成的真实验证

使用 bill 店铺（用户已授权）在独立环境直接连接 Ozon。所选真实商品准确关联来源采购 SKU，并读取了采购价，数量 1、包装重量 30 克；商品身份与具体经营金额仅留本机证据。

真实调价成功，随后恢复原价成功，最终 Ozon 只读回查确认已恢复。两个动作共发送两次价格写请求，旧平台任务请求为零。试算同时返回固定费、物流费、佣金和参考利润；具体商品金额仅留本机证据。

真实 DSH Web Host 已验证：无需聊天保存规则、读取新修订、恢复原方案、按保存的规则试算以及测试店铺连接。界面组件测试覆盖切换方案/店铺、旧报价失效、保存期间禁止编辑、店铺保存不丢失未保存规则稿。浏览器自动化访问测试页被客户端拦截，因此没有把此次验证写成完整的可视点击验收。

本轮没有重新发布新的真实商品或报名真实活动；这两类动作已覆盖直连接口、审核与状态测试，不能据此声称已获得真实平台发布/活动资格。
