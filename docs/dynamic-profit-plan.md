# 动态利润计算修正方案

2026-10-10。用户确认：新应用独立维护利润模型，由实际售价与重量自动匹配物流方案，再结合采购成本计算利润率。135 是用户描述的方案分界，不应由导入程序当作售价上限。

状态：已按本方案实现，candidate.58 已安装到 DSH，bill 动态规则 v2 已启用。最终 293 项相关回归通过，实际 Host 与 Agent 试算通过；详见 [执行及使用记录](dynamic-profit-20261010.md)。

## 已确认的输入和规则

- 已售商品取 Ozon `marketing_seller_price`，普通标价单独保留；它不是扣除佣金运费后的财务结算净到账。
- 待上品/调价/活动操作取本次预计价格。程序计算一次，表格、Agent 与提交使用同一结果；恢复价格也重新匹配当前方案。
- 采购组成与成本保留准确关联；重量使用有来源的实际物流重量，缺失时采用包装声明重量，不能虚构重量。
- 原平台代码仅有统一费率：固定 3.16 元、39.3 元/kg、佣金 20%。用户进一步确认方案 2 只将固定费改为 18 元，其余不变。依照“跌破 135 切回方案 1”，采用售价 <135 元匹配方案 1、售价 ≥135 元匹配方案 2；135 不作为自动上品售价上限。
- 用户确认以后新增方案条件重合时取贵：在当前售价和重量下分别计算固定费、重量运费、佣金，取合计费用最高的匹配方案；费用相等时以稳定方案 ID 决定展示，不影响利润结果。

## 实施

1. 在共用计算器加入售价、重量区间自动匹配。边界显式表达，返回所用方案、匹配依据、规则版本和费用。无匹配时给具体问题；多个匹配时按用户规则取费用最高者。
2. 求建议价时逐个有效区间计算并复核所属方案，重合区间须所有匹配方案均达到目标，避免价格与物流方案循环依赖。跨方案费用可跳变，不能把某个方案算出的最低价当作全局利润保证。
3. 普通利润列表、筛选与采购对照接入同一计算器和规则修订；规则变化使计算缓存更新。历史经营回执保留原计算证据。
4. 设置页维护分段条件与费用；经营表以自动识别方案为默认展示，手动售价不等于手动选择物流。旧固定方案兼容可读取，明确标识，不冒充动态匹配。
5. 只有明确由旧参考导入的 135 上限可纠正；用户另设的真实售价上限保留。bill 已导入的旧参考规则迁为用户确认的两段动态规则，保留既有利润目标，不新增利润底线；历史版本保留。
