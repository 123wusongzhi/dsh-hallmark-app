# candidate69 发布说明

日期：2026-10-10（北京时间）。Bundle、Host 插件与 Runtime 均为 `1.0.0-candidate.69`，数据库 schema 为 4。本版汇总 candidate55 之后的累计改动，已安装到正式 DSH Desktop，保留已有业务数据与配置。

## 功能

- 经营应用自行维护店铺连接、Ozon 请求、异步导入状态、销售与采购关联。采集资料当前通过旧平台适配器读取，未来可替换数据来源。
- 经营设置维护物流报价、价格与利润规则。按实际卖家售价和重量匹配物流方案；多个方案适用时选择费用最高者，缺少数据时保留未知。支持单 SKU 和组合销售的尺寸、重量维护。
- 采集接口提供精简搜索卡片、默认事实与 SKU 表、分页续读、原始依据及图片资源；区分事实未知和尚未展开。`hallmark.listing.prepare` 组合采购资料、包装、经营规则、已有销售关联与类目资料。
- 单规格、多件装及多 SKU 组合沿用稳定采购身份和数量关系。Agent 制作标题、属性、详情与图片；程序承担计算、请求身份、平台结果跟踪和统一提交审核，不要求制作 Agent 登记“已看过”声明。
- 采集箱区分在售、无库存、处理中、归档、失败和未知。普通与归档目录完整同步，归档保留采购关系；搜索或准备上品时按 5 分钟缓存检查更新，主动刷新可立即同步。同步失败不把未知商品当作从未上架。
- 图片审核使用 OpenRouter 原生图片 Decisions 通道和三类固定问题：主图规格文字、成图文字清晰度、成图与来源主体一致性。没有相关文字返回不适用；低信心或服务不可用转独立审核子代理。`referenceSubjects` 仅用于指出来源图片中的比较对象。
- 合并会话组件、收藏和工作台交互，以及大结果分块、缓存复用、局部预览恢复和请求等待等性能改进。

## 验证

- 发布前当前源码与已安装 candidate69 的 256 个构建输入哈希全部一致；65 个已安装产物、实际 Host 提供的客户端及运行中 Runtime 校验通过。发布前 TypeScript 检查再次通过。
- 采集箱销售状态相关测试 137/137 通过，图片审核与经营相关测试 161/161 通过；两组存在重叠，不相加作为全仓库测试总数。
- bill 店铺真实只读核对 420 个销售商品：241 个在售、131 个归档、10 个无库存、38 个发布失败。归档及既有采购关联保持；此次状态及图片通道更新没有向 Ozon 提交经营写入。
- 上品流程此前在 candidate65 的真实 DSH 会话中完成两款商品、每款 5 个 SKU 的创建和平台审核。10 行库存为零，不能表述为可购买；该记录不是 candidate69 的新一轮上品验收。
- candidate69 原生图片通道实际请求成功；两道文字题返回不适用，主体题因低信心保留待审核。该独立探针未接入回退子代理，不能据此声称真实回退已完成或全部图片质量通过。

详细行为与边界见 [采集箱状态](collection-store-status-20261010.md)、[图片审核](decision-review-service.md)、[采集与上品蓝图](collection-blueprint-v2.md)、[性能优化](performance-optimization-report-20261010.md)。历史 A.2 验收及未覆盖的桌面交互项仍按原记录，不由本次发布自动改为通过。
